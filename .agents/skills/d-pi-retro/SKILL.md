# 有证据的复盘

对象是 Agent 的工作环境：导航、工具/信息访问、检查与判断规则。不是重写产品或把一次 review 自动升级为全局政策。先读[任务约定](../../../docs/agents/issue-tracker.md#reviewpr-与-retro-收尾)与用户指定 session；默认当前会话。

## 找证据

读取真实会话记录、失败输出、commit、review 和验证记录；摘要只作导航。只访问任务需要的内容，避免秘密与业务全文进入报告。原始会话不可用时明确来源限制，已有仓库证据可继续分析，不编造 Agent 曾犯的错误。

先查 `package.json` 的 checks、[工程入口](../../../docs/engineering/checks.md)、hook/CI、现有合同和 skills。已有检查没接线或无声失败，优先修它，不另建相同系统；项目 hook 显式安装，仓库有文件不等于该 checkout 已生效。

将每个候选写成：原始证据→可重复成本/错误→根因及确定程度→最小改进位置→验证办法。一次高影响问题也值得修，不要求等重复事故；偶发、已解决或无法证明可复用价值的事项可不做。

| 证据支持的问题 | 回流位置 |
| --- | --- |
| 可机械判断的模式、路径、import/API、依赖错误 | 现有 lint/check/test，验证正例与负例并接入真实入口 |
| 跨文件判断、所有权/恢复等行为合同不清 | 所属合同；skill 提供有条件的操作路由，不复制合同 |
| 找不到实际 owner 或资料 | 模块页/AGENTS 的简短导航指针，修失效链接 |
| 同词异义或缺领域定义 | GLOSSARY；UI 用词仍归 product-terminology |
| 工具输出过大、反复重读或必需信息缺失 | 缩小/批量查询，接入已有只读能力；访问新账号/外部数据遵从授权 |

## 建议与实施

按实际影响给少量可行动候选，可以零项。默认用户选择后再改；当前用户明确授权工作流优化且候选属于该范围时可直接实施，不重复确认。两种模式都不修改个人全局 AGENTS、全局 skills 或 Codex memory，除非本轮另有明确授权。

优先最小修复、删除失效/无行为作用的指令，保留决定的来源和取代关系。无法机械化的判断放现有合同/skill，不新增万能 CODING_STANDARDS；不为每次会话给根 AGENTS 追加规则。不悄悄改产品、权限或既定方向；只暂停依赖重大选择的部分。

实施后验证问题确实被解决、正确路径仍能通过，并检查入口可发现、指令不冲突、没有扩大范围。结论记入所属 spec/票或一次简短 retro 记录，区分 proposed/applied/declined，链接修复 commit 和证据；下一轮有新证据再迭代，不建立自动自我改写循环。
