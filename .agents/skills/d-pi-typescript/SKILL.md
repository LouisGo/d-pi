# d-pi TypeScript

落实 D-35 的[TypeScript 合同](../../../docs/architecture/typescript.md)：按当前任务读取相关节，复用已读且未变化的内容。本文引用已有项目标准，不另建一套类型/状态/校验框架，也不扩大当前任务授权。

业务事件、命令、状态、结果和视图映射优先用判别联合与 ts-pattern，封闭集合穷尽处理；简单布尔/空值返回直接表达。外部值先作为 unknown，经 Zod v4 在信任边界解析后推导类型；可信内部函数不重复校验，schema 成功不替代授权、版本/代次检查或持久接受证据。

设计类型时优先让不合法状态和遗漏在编译期暴露，保持公开合同、数据拥有者和副作用归属清楚；避免断言逃逸、同构类型双写和过度泛型。图标、Base UI、Tiptap、SQLite 驱动等供应商类型留在对应适配层，业务 DTO 可序列化。

实现后按影响检查严格类型、Biome 和有意义的行为/边界样本；必要时用编译期反例验证漏分支或 ID 混用。评审只报告当前范围有依据的缺口，不把小改动扩成全仓改写。交付实际验证与未覆盖项，不把采用这些库当作质量已经达标。
