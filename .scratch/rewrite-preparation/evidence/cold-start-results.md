# 同题 Agent 冷启动结果

2026-09-30 的固定评测快照，不维护项目状态。当前工作状态回到 [spec](../spec.md)，正式构建见 [交接](../handoff.md)。

五个原题均完成，关键约束可发现并落实；本轮数据**不支持接手用时降低的结论**。三组实现复测的观察用时都高于基线，不能写为效率验收通过。文档入口与正确性的工程改善有实现和回归依据，普遍接手成本改善仍未证实。

## 条件与差异

原题逐字固定在 [设置快照](cold-start-setup.json)。基线为 `4adea8299a254df56664c0b3bc00c71abcd01383`；复测五组均为独立本地 clone、干净 detached HEAD `f5e998f1e3f4c5ed1deaa0faf0e33ae75912e379`。每组 `fork_turns: none`，只接收原题、所在 checkout 和操作边界；未注入本轮复盘、评分清单、另一组结果或主 Agent 的调查答案。主 Agent 在完成后读最终 diff/设计，未将评测实现搬回生产源码。

同一会话的模型/推理配置和工具权限继承且未覆盖，未显式改变预算；协作工具没有暴露精确模型 ID、内部推理设置或 token 计数，不能据此宣称已完全控制这些变量。外部文档访问权限与记忆访问权限一致，未主动提供不同的外部资料；没有逐次网络延迟或记忆读取用量。仓库 AGENTS、skill、文档和源码按各自版本加载，本身就是被测改动。

实现组共用独立 dependency-only 快照的冻结 `node_modules`，使用固定 Node 24.21.0 / pnpm 10.5.2 和受控 test environment；App/OMP/HOME/XDG/Git/项目目录隔离，无个人凭据、全局 OMP 或主 checkout 的 SDK。禁止各组安装、准备 SDK、操作 GUI、commit/push。final 的 `node_modules` 符号链接在 Git 显示为 untracked，这是共同注入的依赖入口，不是 Agent 源码改动。

基线首次本地查询遇到 Electron 初次导入下载和 Git 测试超时，共享依赖的准备状态随后发生变化；故在依赖完整后按原题另起上下文补跑该基线，保留两次结果。基线目录由 archive 导出而无 Git 元数据，final 使用真实 clone；构建标识和 Git 默认状态因此不同。并行评测与主 Agent 的 SDK 准备/打包/检查共享同一台机器，未固定 CPU、I/O 或消息观察延迟。部分组选择的验证范围也不同。这些差异均限制用时归因。

正式交付后来为 `441b27b`：在 f5e998f 之后只增加 CR 预览显示补修、对应测试、随包检查和工作记录/生成报告；五组评测没有改换提交，也不把正式包 SHA 冒称评测点。
