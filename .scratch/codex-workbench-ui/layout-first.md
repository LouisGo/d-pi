# 基础布局第一轮：范围、依赖与开工条件

2026-10-06 初版；2026-10-07 按用户确认的三层布局更新当前范围。最初 A0–A3 实施与验证属于历史，当前改动由[05](issues/05-sandwich-layout.md)维护。用户已要求先完成布局，组件和业务按依赖有序推进；取消 normal/compact 切换，以原 compact 尺寸作为唯一默认紧凑布局。调查源码基点为 `1f591f4`；用户随后明确要求将设计成果本地提交，新会话必须核实最新 HEAD 并接续这些成果。

权威入口：[设计合同](../../docs/architecture/design-system.md)、[决定登记](../../docs/decisions.md)、[范围](spec.md)、[布局机制](layout.md)、[组件地图](components.md)。后续实现的授权以用户在新会话提交的请求为准。

## 1. 第一轮用户可见结果

先交付一个可继续使用现有业务的桌面工作台外壳：Thread 列表底部固定横向功能导航、可调宽上下文侧栏、主会话、右工作区宿主，以及底部工具宿主。顶栏与各区域边界对齐；现有创建/切换 Thread、输入、阅读、配置、提醒和诊断入口继续可用。取消密度切换，统一默认紧凑布局；light/dark 均可切换。

第一轮的核心是区域拓扑、空间预算、拖拽/收起/恢复、滚动、焦点和资源连续性，不是一次完成所有业务视图。

| 纳入第一轮 | 明确留给后续 |
| --- | --- |
| WindowFrame、WindowHeader、SidebarActions、WindowStatusbar、PrimarySidebar、ConversationSurface 的布局组合 | Composer 的全面视觉/功能重组、附件/模型/提交组件体系的全量建设 |
| AuxiliaryWorkspace / BottomPanel 的宿主、最小标签交互、自有分隔面板适配与可见性 | 文件/Git/子 Agent 全部业务迁入页签及复杂页签重排/最大化 |
| 真实项目/Thread 导航接线；底部功能入口只提供设置与开发工具，不展示 Home icon | Space、Schedule、插件、Goal/Plan、账户/Usage 等新增功能 |
| 最小需要的自有 Button/IconButton、Tooltip/Menu 等复用或封装；集中视觉角色 | 先建完整组件库/Gallery、全局目录大迁移、单独 npm 包 |
| 默认紧凑尺寸、取消密度切换、旧偏好兼容、两主题与受影响颜色关系 | 第二套密度、字体设置产品、主题编辑器 |
| 独立阅读/输入预算；原导航准入、编辑与阅读资源保留 | 修改 OMP、收据/unknown、队列政策、认证和 Git 写行为 |

右/底宿主没有真实内容注册时在生产保持关闭，不展示可操作的假终端、浏览器或子 Agent 数据。第一轮可在隔离 GUI 验证宿主中注册轻量内容，覆盖三条分隔边与页签行为，测试内容不得进入生产。现有文件/Diff 等阅读入口可以先保持原位置；其正式迁入归后续 C 切片。只有不会扩大业务重组且能保留单一资源拥有者时，才在本轮接入一个已有只读页作为最小真实辅助闭环，并记录实际覆盖；不是前置条件。

## 2. 依赖顺序

```text
A0 共享视觉角色 + 唯一默认尺寸 + 最小自有组件 API
                       ↓
A1 纯几何约束 + 自有面板适配 + 展示状态合同
                       ↓
A2 工作台外壳 + 现有导航/阅读/输入接线
                       ↓
A3 两主题、连续性、拖拽、窄窗口的实际 Electron 验证
                       ↓
可识别本地试用交付

之后：B Composer 组合；C 真实辅助内容迁入；D 按 M2 票补齐；E M3 逐功能
```

A0/A1 可以在同一切片中交错准备，但 A2 不能先用任意视觉值或重复几何搭起来再补合同。A0 只补外壳真正用到的角色和控件，不要求完整组件体系先完成。后续 B/C 可以按实际独立闭环推进，不要求先完成所有输入业务才能迁入一个只读辅助页。

| 步骤 | 开工前确认/主要工作 | 可核对的结果 |
| --- | --- | --- |
| A0 | 盘点实际 token/组件；控件、容器、浮层等角色；对受影响主色状态和辅助文字建立同源关系；移除产品密度选项 | 同一基础组件在导航/工具栏/配套动作一致；默认尺寸只有一套，旧字段不决定 UI |
| A1 | 固定顶中底三层与左/主/右+工具宿主拓扑；纯预算规则；薄封装成熟面板能力；期望尺寸/有效尺寸/手动关闭/暂藏区分 | 临界尺寸、阈值、恢复、取消、键盘与偏好规则的行为证据 |
| A2 | 现有 Router/AppModel 准入与 Thread 资源；单一 Tiptap；标题/体区同一几何来源；保留低频入口 | 新建/旧会话/切换/空态与错误态可以继续使用，拖拽不初始化业务 |
| A3 | 原生标题栏、最小窗口、两主题、焦点与输入；说明生产宿主和隔离验证宿主覆盖 | 当前构建的测试与视觉证据、可操作试用步骤、剩余边界 |

## 3. 本轮工程默认与调整边界

- 固定顶中底三层；28px 状态栏分段跟随实时列宽。底部工具宿主位于中间主会话/右工作区下方；左导航底部固定设置/工具行。不引入自由分屏/docking，底部跨度是可逆工程默认，不冒称截图已证明。
- Grid 外壳、内部一维面板与 Flex 内容区；`react-resizable-panels` 是已有源码证据支持的优先候选。实施时核实发布版本/React/Electron兼容并锁定，库导入仅在自有适配内部。未发现关键不适配前不自研完整拖拽引擎；如果不适配，记录具体证据并选最小替代，不暂停整个布局工作。
- 几何只有一个拥有者。默认/最小/最大尺寸按已有候选和真实内容预算调整；阈值考虑原始手势及恢复滞回，不能先 clamp 后失去拖拽关闭。用户期望尺寸与窗口临时可用尺寸分别表达，自动暂藏不覆盖手动偏好。
- 在 720×540 及实际窗口预算中保护主输入/阅读。空间不足先暂藏左导航（提供明确入口），再暂藏辅助/底部宿主；不改变手动关闭偏好，不提高窗口最低宽度来规避问题。窄窗口的真实文件阅读继续使用既有阅读入口，本轮不新增完整的辅助内容全屏模式。
- 只在实际有对应内容时显示生产页签和面板入口；保留已有功能的明确入口，不复制 Codex 的账户或未实现功能。
- 首轮新增外壳/技术组件优先保持 app 内归属；不用跨模块共享库迁移作为前置。确实需要新增公共 UI 归属时按机器清单处理，不反向导入 app 私有组件，也不复制第二套基础控件。
- 默认 token 使用原 compact 尺寸；撤下密度切换、命令与分支。旧 density 字段在 preferences 边界兼容，产品外观 API 不再把它当设置；旧数据不重建。主题继续沿用 preferences，保存失败与恢复语义不变。

## 4. 验收范围

1. **体系与主题**：light/dark、默认紧凑布局；相同控件在不同组合中的圆角/文字/尺寸/交互一致，Portal 同源；集中主操作/辅助文字角色修改能传播到代表性消费者和状态，不留旧局部色值。没有第二套密度入口/样式分支。
2. **几何**：左/右/底边的拖拽、上下限、阈值收起、明确恢复、窗口缩小后恢复、pointercancel、键盘和关闭焦点。纯规则先写能暴露缺口的行为测试，再接正式 GUI；不只断言实现中的常量。
3. **可用性与连续性**：最小/普通/大窗口、中英长文案、默认尺寸下的实际输入/阅读面积、独立滚动、主操作可达；正文/附件/撤销/IME/阅读坐标及原有阅读入口保留。Thread 选择确认/unknown 和迟到保护仍有效。
4. **成本与原生**：真实 Electron 拖拽、标题栏命中、浮层/分隔条、Monaco 受影响尺寸；流式内容与输入不因拖拽重建资源。按实际风险测量，不把 React 渲染次数或静态截图当流畅证明。
5. **工程与交付**：按仓库约定完成受影响测试、设计/i18n/架构/文档门禁、构建及必要实际 GUI 检查；不关闭规则。交付本地提交/构建身份、试用步骤和未覆盖内容，工程通过与用户认可分开；不自动 push/merge/公开发布或发起真实账户请求。

本轮只准备上述范围，不执行产品验证。底部/右宿主仅有隔离样本时明确记为容器验证，不能称为终端/浏览器/所有辅助业务可用。

## 5. 开工判断

方向、角色规则、主题要求、默认尺寸、第一轮范围、依赖和关键验收已明确，可以启动 A 基础布局切片。具体面板版本、最终阈值、组件拆文件及样式表达是实施时可核实的工程选择，不需要重开全局选型或等待全部组件设计完成。未确认的 M3 生命周期/Goal/Plan 等不参与第一轮，不阻塞开工。

下一会话先读取本页和相关合同，核实 HEAD、并发工作与文档改动；将第一轮范围写成可领取任务并从 A0/A1 开始。在同一 checkout 继续时保留当前文档；需要隔离 worktree 时从包含本轮设计成果的提交接续，并保留后续可能出现的未提交改动，不能漏掉新要求。新会话用的完整请求见[开工 prompt](next-session-prompt.md)。
