## 2. 推荐拓扑

```text
WindowFrame
┌───────────────────────────────────────────────────────────────┐
│ WindowHeader：原生控件/导航 │ title/导航标签 │ 可选工作页签       │
├──────────────────────┬────────────────────┬───────────────────┤
│ PrimarySidebar       │ ConversationSurface│ AuxiliaryWorkspace│
│ 项目/Thread 列表滚动  │ 阅读/输入           │ 页内容独立滚动     │
│                      ├────────────────────┴───────────────────┤
│                      │ BottomPanel：按需工具宿主               │
├──────────────────────┤                                        │
│ Settings（宽） Tools │                                        │
├──────────────────────┼────────────────────┬───────────────────┤
│ 版本号               │ 对话快速预览        │ 区域状态预留       │ 28px
└──────────────────────┴────────────────────┴───────────────────┘
```

顶栏、内容、状态栏由整窗外壳固定分为三行。底部工具宿主位于中间内容区，不推挤顶层导航，也不是状态栏。左侧功能导航是 Thread 列表底部固定的独立行；无 Home/会话 icon，设置占左侧宽区，开发工具占右侧窄区，工具菜单向上弹出。设置沿用大 Modal，背景资源保持挂载。

左/主/可选右区域的顶栏与状态栏按实际列宽对齐，拖拽中也跟随，不平均分栏。布局意图仅由原模型持有；面板库的实时几何通过 ResizeObserver 映射到外壳 CSS tracks，不写第二份偏好。收起左栏时版本移入主段，设置/工具通过导航覆盖层恢复；覆盖层转设置时关闭导航层，设置关闭返回顶栏导航按钮。开发者工作区仍覆盖完整内容宽度，顶栏提供“返回会话”，返回保留 Thread 资源及原布局意图。

状态概况只消费当前 Thread 的已有投影：执行状态、模型、当前实时窗口用户/助手消息数量、排队及后台任务；点击/键盘打开快速预览，含目录与来源范围。消息数不是全历史轮数，工具/notice/subagent 不计入用户与助手消息；gap 明示不完整。未同步、无能力的数据与合法 0 区分；token/cache/context 尚无完整公开投影，不伪造数值，也不借布局启动新的原生采样。

固定左/主/右内容拓扑与按需底部宿主；不引入自由 docking、多编辑组或任意拖出浮窗。沿用 D-16。

## 3. CSS、几何与交互分别做什么

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| CSS Grid / Flex | 窗口轨道、内容填充、局部工具栏、溢出、局部容器查询 | 手势状态、持久偏好、是否结束终端/Agent |
| 几何规则 | 依据内容盒和最小尺寸分配区域；计算可见轨道/有效尺寸 | 查询 Thread、改变权限、决定 OMP 是否 ready |
| 可调整面板组件 | 指针/键盘手势、吸附收起、分隔条命中区与反馈 | 业务队列、文件内容和外部网页资源 |
| 工作台展示状态 | 用户期望尺寸、收起意图、页签列表/选中、最大化、最近焦点 | 第二份草稿、原生执行状态、可独立修改的 Query 数据 |

推荐 **Grid 外壳 + 内部一维分隔面板 + Flex 内容区**。成熟面板库可自行输出 Flex；不为了“全 Grid”覆盖其内部尺寸样式。外层约束与内层组件通过明确的尺寸/折叠合同配合，只有一个拥有者对每条分隔边写几何。

CSS 的关键结构规则：

- WindowFrame 占据窗口内容盒；根层禁止页面滚动。WindowHeader 为固定行，剩余行使用 `minmax(0, 1fr)`。
- 可缩小的 Grid 轨道使用 `minmax(0, 1fr)`；所有可缩小的 Flex/Grid 内容宿主明确 `min-inline-size: 0` / `min-block-size: 0`。否则文件编辑器、长路径或旧内联宽度会反向撑开窗口。
- header 的标题分界与 body 分隔边消费同一组已解出的 CSS 变量；不要独立测量两遍，也不要用相邻 DOM 的百分比猜位置。
- 会话垂直分成阅读 `minmax(0, 1fr)` 与输入/交互 `auto`。正文最大行宽仅施加在阅读内层和 Composer，不施加到整个 WorkArea；文件/终端需要使用可分配面积。
- 阅读、导航列表、辅助页内容、终端各自滚动；头部、标签栏、Composer 操作区保持可达。附件行可横向滚动，编辑正文独立纵向滚动；不让整个 App 出现横向滚动条。
- 区域间使用默认4px透明留白，不绘制静止分割线；顶栏使用surface，底部状态栏使用略有区分的统一muted底色，各状态段保持透明。手势命中区需要更宽，仅hover/drag/键盘焦点提供反馈；命中区以分隔边为中心，不能挤占两倍空间或遮住近边按钮。
- 普通文字允许换行，路径/URL 给出省略和完整值入口；代码/Diff 用自己的滚动策略，不把整份代码强制断词。
- CSS Modules、Tailwind、全局 CSS 按现有可读性组合。颜色/字号/密度消费 `tokens.css`，动态几何允许受控 CSS 变量；不另建 CSS 框架。

## 4. 尺寸不是固定值，也不是纯百分比

定义：`W/H` 是工作台内容盒；`L/R/B` 是左栏、右栏、底部尺寸；`Cmin` 是主会话最低宽度；`S` 是当前实际占位的分隔条总宽度。视觉覆盖型命中区不重复计入 `S`。

横向可行条件为：`L + Cmin + R + S <= W`。

右侧有效上限来自：`Rmax = min(设计上限, W - L - Cmin - S)`。左侧类似。`Rmax < Rmin` 时是并排布局不可行，应该切换呈现模式，不能简单 `clamp` 到一个比可用空间更大的最小值。

| 区域 | 推荐初始范围，CSS px | 上限与意义 |
| --- | --- | --- |
| 全局状态栏 | 28px，集中 token | 固定底行；中间可用高度先扣除顶栏和状态栏 |
| 左导航 | 初始约 280，最小约 220 | 候选上限 `min(420, 可用宽度的约30%, 保留主内容/已开右栏后剩余空间)`；短标题不是无限缩小的理由 |
| 主会话 | 候选并排最低约 480 | 对话本身适应更窄容器；低于并排预算时先改变区域呈现，不堆叠不可用的窄栏 |
| 右工作区 | 初始约工作区的 40–45%，一般最低约 320–360 | 上限同时受主会话预算约束；不同内容可声明需求，浏览器和 Diff 不被一刀切成 300px |
| 底部面板 | 初始约 220，一般最低约 140 | 候选上限约工作区高度的55%，还必须给阅读与 Composer 留空间；二者取更小值 |

上述均为设计候选。中文/英文、默认紧凑布局、light/dark、系统缩放、附件高度、模型名称与实际组件决定最后阈值。DeepSeek 源码同时包含固定的最小/最大宽度和比例上限；ZCode 也使用最小像素、比例与内容预算。因此“最大宽度一定完全动态计算”不能作为事实。

高度也要整体预算：剩余高度至少包含阅读可用高度、Composer 的当前最小操作高度和必要标签栏。长稿/附件/待答出现时先让各自正文滚动，保留操作行；必要时自动收起底部、进入展开输入/内容聚焦模式。不要给每一层都设独立 `vh` 上限，最后把阅读挤到零。

布局 state 分两种：

| 用户意图/偏好，可保存 | 当前派生结果，不覆盖偏好 |
| --- | --- |
| 期望左/右宽度、底部高度、最近展开尺寸、手动开/关、选中页签 | 当前内容盒、有效宽高、响应式暂时隐藏、并排或聚焦模式、拖拽预览 |

关闭后记住最近展开尺寸；窗口变窄不把偏好改成零；重新拖拽以**当前实际呈现尺寸**作为起点，防止跳回保存值。窗口重新变宽可以恢复响应式暂藏，但用户手动关闭的区域不能自动重开。

尺寸以像素偏好保存，第一次打开右侧可用比例初始化；比例只是初始意图，不要求窗口扩大时左导航无限变宽。保存按真实窗口/工作区作用域定义，不能按数组位置绑定到错误面板。

## 5. 拖拽、吸附关闭与恢复

一次手势的行为合同：

1. 仅主指针开始；捕获 pointer，记录手势起点和实际尺寸。水平/垂直使用同一交互原语，规则由所属区域提供。
2. 根据原始候选尺寸决定是否跨过关闭阈值，随后才约束正常展开尺寸。先钳制到 `minSize` 再判断，永远不可能吸附关闭。
3. 到阈值后可呈现收起预览，松开提交与关闭按钮相同的展示意图；同一手势仍能拖回展开，边界使用迟滞，避免来回闪烁。
4. 区分最小可用尺寸、关闭阈值和重开阈值；可采用成熟库的折叠阈值合同，但数值要通过实物验证，不能把“拖小消失”理解为宽度无限接近零。
5. `pointerup`、`pointercancel`、捕获丢失、视图销毁都清理手势、光标、遮罩和调度。不能留下全 App 无法选字的状态。
6. 收起后按钮/快捷键可重开，恢复最近展开尺寸并再次受当前预算约束。隐藏区域里的焦点必须回到可见入口或最近主会话焦点，不抢走原本在别处的焦点。

键盘分隔条提供名称、方向、当前/最小/最大值；方向键调节，提供明显的收起/恢复动作。标签栏左右导航、关闭页签与返回编辑区各有键盘入口。实现时验证屏幕阅读器与 Base UI 焦点组合。

拖拽是高频几何交互：不写入主 AppModel 导致整棵聊天树重跑；预览更新限制在布局/适配层，持久保存发生于手势完成或明确合并后的时点。库可能已经合并更新，不叠加第二套 rAF 造成延迟。手势和窗口连续 resize 期间关闭尺寸过渡；按钮开关可以有短过渡，遵守 reduced-motion。

## 6. 响应式按区域预算处理

宏观布局使用容器实际内容盒的约束判断，不单纯 `window.innerWidth`。局部组件使用容器查询；必要时用少量 ResizeObserver 测量真实文字需求，不能每个按钮都建一套抢空间 observer。

| 情况 | 推荐策略 |
| --- | --- |
| 区域预算足够 | 左导航 + 会话 + 右工作内容并排，底部按用户选择出现 |
| 左/右展开挤占主会话 | 先压缩低优先级信息、约束辅助尺寸；仍不够则优先暂藏左导航，保留当前显式打开的辅助内容 |
| 两个工作面仍不足 | 右内容切为工作区聚焦页，保留返回会话入口；同一资源/选区不重建。此策略是候选产品行为 |
| 窄窗口主动打开项目导航 | 以可关闭的导航覆盖层出现，选中后回到工作区；不把永久多列缩成文字碎片 |
| 矮窗口/展开长稿 | 阅读与编辑正文滚动；底部可暂藏，展开输入保证操作行可达；待答不能被无提示隐藏 |
| 当前最小窗口 720×540 | 移除一级栏后，两列满足最小预算时保留左栏；右区展开造成不足时先暂藏左栏，再暂藏右区；状态栏始终保留；不擅自提高窗口最小尺寸掩盖缺口 |

显式操作可以提升某个区域优先级；窗口自然缩小和用户点击“打开文件”不能完全采用同一“总是先关右侧”规则。自动变化只改派生呈现，不改业务状态或用户保存的开关。

Composer 工具栏收缩顺序建议：缩短非关键说明 → 模式/扩展低频入口移入更多菜单 → 模型名省略但保留可查完整名称 → 必要时分两行。提交/停止、附件失败、发送阻断原因保持可达；权限不能仅用无说明色点表达。容器查询优先，只有内容尺寸变化无法靠 CSS 处理时再测量。

Diff 窄区域可用单列/内联对比模式；文件树窄时用独立开关暂藏；补全浮层按 Composer 与窗口可用高度限制并内部滚动，不能超出窗口或躲到终端背后。

## 7. 标签、资源和焦点是三种状态

辅助页签使用稳定身份和类型：文件含工作目录身份与实际路径；Diff 含来源、比较范围与版本；子 Agent 页含 Thread；未来浏览器含浏览资源 ID；终端含 PTY 会话 ID。标题仅展示，绝不能作为 identity。

| 动作 | 布局效果 | 资源效果 |
| --- | --- | --- |
| 换页签 | 当前面可见，旧面停止无必要绘制 | 原生业务不结束；按资源策略保留或重建视图 |
| 收起右/底部区域 | 不占空间，记住最近尺寸与页签 | 不终止 Agent、终端，不删除 Side Chat 历史 |
| 关闭文件页签 | 移除页面入口 | 释放视图监听/编辑 model 引用；未来脏文件有保存决策 |
| 关闭浏览器页签 | 移除页面入口 | 明确释放该网页资源，共享登录仍归引擎 |
| 关闭终端会话 | 独立终端命令，不等同收起 | Main 处理真实进程和退出，具体提示到 M3 明确 |
| 切换 Thread/项目 | 经过原有导航准入与真实身份确认 | 不靠 Router 卸载决定 OMP 是否结束 |

不能“全部页签永远挂载”也不能“全部切换立即销毁”。Tiptap 的正文/撤销属于 editor；Monaco 可以保留 model/选区并释放不必要 DOM；原生网页/PTY 的存活由 Main 管；轻量只读页可重挂载并恢复坐标。隐藏的编辑器不按 0×0 无意义反复 layout，重显后再处理有效尺寸。

顶栏空白可以拖窗口，按钮、标签、菜单触发器、分隔条必须可交互；Electron 的 `app-region` 是几何区域，不能以高 z-index 保证点得动。原生嵌入页面若在 DOM 之上，Portal 也不能靠 CSS z-index 压过它：以后选择具体嵌入 API 时必须核实浮层/拖拽遮挡策略。

## 8. 与当前 d-pi 的距离和验证

2026-10-06 调查时 `ApplicationLayout` 是两列 Flex 外壳，侧栏固定 token 宽度；`ThreadWorkbench` 在中间堆配置/模型/运行区域，再用会话/文件/收据/历史四个阅读页签切换。整个 `.work-content` 受 `--content-width` 限制。没有本方案的一级栏、外层右工作页签/底部面板或通用拖拽机制。来源见[当前源码](research.md#当前-d-pi-证据)。

迁移首先改变应用组合和几何，不替换 input/files/changes/conversation/execution 的领域合同。将宽度限制下沉到阅读/Composer，顶栏与设置减少占据主阅读空间。Composer 保留单个 editor 实例；文件/Diff 可迁入右侧，并继续保留原有来源标签。

后续最小有意义验证：

- 纯规则：预算临界点、无可行区间、不同内容最低尺寸、窗口收缩不覆盖偏好、手动关闭不自动打开。
- 组件交互：拖到阈值并拖回、pointercancel、键盘调宽、关闭后的焦点、标签增删/溢出；主会话不因拖拽或流式输出重新初始化。
- 连续性：正文/附件/撤销/选区/阅读位置、四个原阅读入口、Thread 切换准入和 unknown 继续有效。
- 原生/视觉：720×540、普通/大窗口、默认紧凑布局与 light/dark 两主题、中英长文案、macOS 标题栏/全屏/系统缩放、中文候选、文件与 Diff 几何。
- 性能：同内容与构建，流式输出时连续拖拽并输入；记录布局/绘制、第三方 layout/fit 调用与输入延迟。没有测量前不设“已达到 60fps”等结论。

本轮没有新 UI；上述验证在[基础布局切片](layout-first.md)与后续受影响切片中按范围执行。2026-10-06 已取消密度切换，原 compact 尺寸成为默认紧凑布局，不要求第二套密度实现或往返矩阵。
