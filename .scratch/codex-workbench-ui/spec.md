## 两项任务的结论

### 布局

外层是桌面工作台，不是普通网页的三栏加若干弹窗。四个横向区域为：一级功能栏、上下文导航侧栏、主会话、辅助工作区。顶栏对齐这些区域；底部面板占用工作区高度。文件页内部的树、Diff 左右对比、浏览器工具栏属于内层布局。

CSS Grid/Flex 负责排版与滚动边界；尺寸约束负责可用空间分配；分隔条负责用户手势；工作台状态负责偏好、可见性与页签。这四项职责分开，才能避免窗口缩放、拖拽、标签切换与流式输出互相干扰。详见[布局方案](layout.md)。

推荐先采用固定拓扑和成熟 React 分隔面板组件。`react-resizable-panels` 是优先候选，不在本轮安装或锁定。借鉴 VS Code 的约束与吸附思想、DeepSeek Harness 的几何分工、ZCode 的布局和 Composer 分工；不搬入 VS Code Workbench、Cordis 插件平台或自由 docking 系统。

### 组件

按职责区分三类：

1. **技术交互组件**：按钮、菜单、Popover、Dialog、分隔条、标签交互、浮层定位与焦点等，不拥有提交、执行或磁盘事实。
2. **工作台组合组件**：窗口顶栏、一级导航、项目/最近列表、主会话外壳、工作页签区、底部面板、设置页面外壳，负责位置与导航意图。
3. **业务组件及适配器**：Composer、附件、模型选择、提交动作、待答交互、队列、子 Agent、文件、Diff 等，消费所属模块的状态与操作合同。Tiptap/Monaco/未来浏览器和终端资源适配另有生命周期。

每个拆分单元以独立的行为、状态订阅、交互协议或资源生命周期为依据。视觉上多一个 div，不是单独拆组件的理由；独立组件也不自动等于独立任务票。详见[组件目录](components.md)。
