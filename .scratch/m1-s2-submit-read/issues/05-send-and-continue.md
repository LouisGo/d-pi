# 05 — 正式输入与同 Thread 两轮真实发送

Status: open
Type: task
Stage: M1 S2
Blocked by: 02, 03, 04
Labels: ready-for-agent

## 目标与依据

串联准入、持久交接与阅读：用户在现有 Thread 发送 A，看到持久发送记录和流式结果，再在同一原生会话发送第二轮；实现正式 Composer 交互并交付可操作体验。

受影响决定：D-11/17/21–26/28–35。共同依据：[S2 spec](../spec.md)、[确认方案](../acceptance-decision.md)、[固定版本证据](../evidence.md)、[基础契约](../../../docs/architecture/foundation-contracts.md)。授权与用户试用状态以 spec 为准；本轮只拆票，未开始实现。

## 交付与所有权

- 复用 01 已就绪 Host、02 提交流程、03 阅读和 04 历史；准确映射原生 requestId/实例到 submissionId。ACK 后仍能识别有限迟到错误，超过窗口保留关联缺口，不猜逐提交执行归属。
- ACK 落盘后消息区原文可查看/复制，输入只消费 A；B/IME/撤销保留。记录失败与 unknown 可见，无自动重试按钮偷渡重发。
- 默认 Enter 发送、Shift+Enter 换行；可切 Enter 换行/⌘Enter 发送，展开临时后一模式，收起恢复偏好。切换不重建编辑器或重置选区/撤销；IME 优先。
- URL 保留目标，本地品牌/通用链接图标走 Icon Layer，不抓网页/favicon。沿用主题/密度和共享组件。
- 空闲才开放本片发送，忙碌保留并保存草稿，清楚提示 S3 排队/控制限制；第二轮必须复用相同存活原生会话。中断后不偷换新会话。
- 新窗口合并持久收据/有效草稿、只读历史与当前投影，明确来源；不得按同文字去重伪装 native 关联。必要持久原文不受投影缓存配额回收。
- 主验收不依赖尚未实现的原生待交互回答；出现待交互时真实显示状态和限制。

## 验收

功能和修复遵循 TDD，先目标失败测试、最小实现、再必要重构；既有正确行为补测不伪称历史红灯。实现前读取适用的 headless-features / TypeScript skill，GUI 另读设计系统 skill。

- A3/A4 的跨边界关键样本：真实官方 ACK、同 ID 迟到错误、保存期间编辑 B、落盘失败与通知丢失；复用 02 单元矩阵，不全量重跑实验。
- A10：隔离确定性模型完成两轮，核对同 Thread/nativeRef、真实输出可复制、第二轮承接首轮；明确这不是真实供应商验收。
- A11：自动交互验证发送模式、展开/收起、IME、链接、编辑连续性；新增主题/密度与视觉交付按设计合同检查。
- 提供当前构建的启动/操作说明与已知限制，及时记录“已交付待试用”；用户没答复不阻止独立的 06，也不记认可。

## 边界与完成

不扩大 S3 控制/恢复、S4 文件/Diff 或 M2 认证/附件/多 Thread；不修改官方 OMP。按风险验证并记录实际结果，无头通过不代表 GUI 或用户认可。阻塞票须 resolved 后开始依赖工作；未知工程细节按现有证据收敛，重要新产品取舍才对齐用户。
