## 目标与依据

用户可看清项目目录与已有配置来源，明确允许执行后进入原生就绪状态；仅浏览时不启动 Agent。交付最小准入界面及其无头逻辑，不发送草稿。

受影响决定：D-02–05、D-21/22/25/26、D-34/35。共同依据：[S2 spec](../spec.md)、[确认方案](../acceptance-decision.md)、[固定版本证据](../evidence.md)、[基础契约](../../../docs/architecture/foundation-contracts.md)。授权与用户试用状态以 spec 为准；本轮只拆票，未开始实现。

## 交付与所有权

- Main 拥有目录身份、持久信任与配置上下文；启动和派发入口再次检查真实目录，browse 不加载项目扩展。撤销先阻止新操作，不把仍活跃的任务说成已停止。
- 使用官方 v18.3.0 受管理资源、版本与校验信息，开发/打包一致解析；不依赖全局 omp。沿用现有 SQLite 迁移约定，不安装未定候选框架。
- utility SessionHost 监督独立 OMP，建立唯一有界 RPC 关联、UTF-8/JSONL/v2 transport 与受限 MessagePort。旧实例/连接不更新当前状态；超限、缺片和退出可解释。
- 配置查询不发计费探针、不复制凭据，模型显示不等于认证可用。创建并绑定本 Thread 管理的原生会话，输出真实 readiness/nativeRef；不得用路径存在冒称已有持久历史。
- 释放进程、端口和监听有明确拥有者；关窗不杀任务。活动退出先拦截并保留当前工作，提示当前阶段控制限制；完整等待/停止退出留 S3。

## 验收

功能和修复遵循 TDD，先目标失败测试、最小实现、再必要重构；既有正确行为补测不伪称历史红灯。实现前读取适用的 headless-features / TypeScript skill，GUI 另读设计系统 skill。

- A1：未信任零 spawn，隔离 sentinel 证明没有加载项目扩展；信任后目录失效不回退。
- A6：跨 UTF-8 块、多行、v2 缺失/交错/超限、旧代次和进程退出；以边界测试证明有界及清理。
- A9 的资源解析/配置失败部分；正式产物两轮由 06 完成。准入界面展示实际状态，主题/密度及权限文案符合合同。

## 边界与完成

不扩大 S3 控制/恢复、S4 文件/Diff 或 M2 认证/附件/多 Thread；不修改官方 OMP。按风险验证并记录实际结果，无头通过不代表 GUI 或用户认可。阻塞票须 resolved 后开始依赖工作；未知工程细节按现有证据收敛，重要新产品取舍才对齐用户。
