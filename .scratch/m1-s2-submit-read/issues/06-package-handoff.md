## 交付与所有权

- 正式产物携带官方固定 Runtime，记录来源/版本/校验、构建 ID 和隔离启动方法；移动到含空格路径后仍正确解析，可写数据不落安装包。
- 覆盖真实打包两轮、流式中关窗重开、活动退出保护、进程故障后收据/原文保留。无可靠证据时不自动追加原生历史或重发。
- 按 spec A1–A11 建证据索引，复用前票与 S1 未受影响证据，标明实际运行环境、模拟/真实 RPC/GUI/供应商的区别。
- 提供选项目→允许执行→发送→阅读→第二轮的试用步骤和预期；保留旧 S1 包/数据，明确新包标识。不使用个人凭据后台探针。
- 真实供应商试用按用户选定配置进行；未试用保留待试用状态。不得把工程绿灯写成用户认可，也不承诺 Windows/Linux、签名公证、干净机器或日常迁入。

## 验收

功能和修复遵循 TDD，先目标失败测试、最小实现、再必要重构；既有正确行为补测不伪称历史红灯。实现前读取适用的 headless-features / TypeScript skill，GUI 另读设计系统 skill。

- A9/A10/A11：新正式产物定向 smoke 及窗口生命周期检查；只有失败/新疑点才扩大。
- 受影响类型、Vitest、Biome、设计 lint/token/Icon 边界及构建通过；已有覆盖不手工逐条重复。Computer use 仅补具体原生/视觉证据并先说明目的。
- 所有关键未知有真实状态，无遗漏的产品阻塞；更新 spec、各票证据与交接。工程交付即可 resolved，用户体验反馈单独留在 spec。

## 边界与完成
