## Problem Statement

S1 已能打开目录、保留稳定 Thread 和保存文字，但用户还不能把输入交给 OMP 执行并阅读真实结果。加入发送按钮不等于完成交接：本地保存成功、IPC 返回、OMP 接受、开始执行、执行结束是不同事实。若混用，断链或迟到回执会造成误清新稿、重复执行或虚假的完成提示。

S2 要在已有可用原生配置下建立一个可追踪、可继续的真实闭环，同时把后续恢复需要的身份、冻结内容与收据留对。

## Solution

用户在现有 Thread 看清实际目录、配置来源和当前模型，显式允许该目录执行后发送文字。应用显示提交状态，持续呈现 OMP 的文字、必要工具状态和结果；第一次工作结束后，在同一 Thread/原生会话继续第二次提交。发送期间可以继续编辑，迟到的 A 调用确认不能清掉 B。

S2 的正常验收入口是闲时文字提交及完成后的再次提交。忙碌时继续保留和保存草稿，清楚标示排队/干预/停止尚属 S3；不以本地缓存自动续发模拟排队，也不改变 D-11 最终普通发送排队的方向。

仅浏览状态可以读本 Thread 已有的可恢复记录，不因查看历史启动 Agent 或加载项目可执行扩展。未确认的提交显示“接收结果无法确认”，保留冻结内容；重新打开、存储重试和检查状态都不自动重发。

## User Stories

1. 作为已有可用 OMP 配置的用户，我希望直接复用配置并看见实际模型与目录，以便知道本次任务会在哪里、用什么执行。
2. 作为项目使用者，我希望先明确允许执行，再启动 OMP，以免打开目录或浏览历史就加载项目代码。
3. 作为输入者，我希望发送确定的正文版本、保留后续输入，以免等待期间修改的内容被旧结果覆盖。
4. 作为任务发起者，我希望分别看到提交调用确认与执行结果，以免把通信成功误认为任务完成。
5. 作为阅读者，我希望看到真实流式文字、工具结果和错误，并能选择复制，以便检查结果后继续沟通。
6. 作为同一 Thread 的使用者，我希望第二次提交沿用原生上下文，以便继续第一轮工作，而不是另开一个无关会话。
7. 作为遇到故障的用户，我希望能查看未确认提交的原文且不会被自动重发，以免重复产生副作用。
8. 作为重新打开应用的用户，我希望能先安全查看已有内容和收据；占用、目录或恢复状态不明时不要悄悄在别处执行。

## Implementation Decisions

### 1. 所有权与生命周期

| 拥有者 | S2 职责 | 不承接的事实 |
| --- | --- | --- |
| Main：Thread/准入 | 稳定 threadId/workspaceId、规范化目录、目录级信任、配置上下文标识、单 App 入口及执行拥有者 | Renderer 的 ready 缓存不是授权；不认同名路径为原目录 |
| Main：输入/提交/存储 | 不可变冻结正文、revision、submissionId、持久收据及条件清稿；复用 SQLite 单写入口 | 不推断 OMP 接受，不复制原生历史或凭据库 |
| utility SessionHost | 监督独立 OMP、唯一 RPC 关联表、固定版本适配、调用确认与原生证据判定、显示投影与历史查询 | 不拥有第二套自动消费执行队列，不靠 React 挂载启动任务 |
| OMP | 执行、工具、原生队列、原生会话/配置/记忆 | App 收据不提供原生幂等或 exactly-once |
| Renderer | Tiptap 编辑、输入协调、只读投影、有限意图和 UI 状态 | 不打开数据库、不持凭据、不以显示状态控制后台生命周期 |

Main 建立受限的 Renderer–Host MessagePort；正文流由 Host 直达 Renderer，Main 只接必要持久化/监督消息。Thread 身份与 processInstanceId/connectionGeneration 分开；旧实例和旧连接回执不更新当前状态。先落实一个前台 Thread，不预建完整模块框架或新后端。

### 2. 从草稿到冻结提交

- 点击发送时捕获正文 A 和编辑序号，分配一次 submissionId；该次操作的重入/重复 IPC 复用此 ID。traceId 只用于诊断。
- 复用现有输入保存协调的串行/CAS 路径，使冻结内容与一个已知持久草稿 revision 对应。不得简单调用“排空到最新稿”后再读取编辑器，否则等待保存期间输入的 B 会替换本次 A。可以继续保存 B，但 A 的冻结副本不能变化。
- 发送准备与后续自动保存共用 revision 交接。S1 当前 `sequence` 是内存编辑序号，数据库 `revision` 是确认保存版本；两者不能混称，也不能仅比较正文相同就认为没有新编辑。
- Main 在事务内登记 prepared、冻结正文及身份/revision/内容摘要/传输表示关联；业务前置条件、容量和目标上下文不成立则保留输入，不进入派发。
- 冻结正文在 S2 可由 SQLite 直接承载，无需为纯文字新建附件平台。它是可恢复业务数据，不写诊断日志。
- S1 UTF-8 4 MiB 是保存上限，不是发送承诺。发送前计算完整 JSONL 编码字节数，以固定版本文档建议的 advertised physical-frame limit 作为保守客户端预算（不是声称原生输入已实测强制此上限）；超限明确拒绝发送，保留可保存原文，不截断、不拆成多条 prompt、不悄悄换表示。未来附件预算不能覆盖此限制。

### 3. 持久收据与原生证据

交接主路径为 preparing → prepared → dispatching → acknowledged。prepared（含冻结正文）与 dispatching 分别确认落盘后，Host 才能写一次原生命令。派发许可绑定 Thread、配置上下文、原生目标和实例身份；写入前再次检查，不能把旧许可用于重启后的进程。

| 触发 | 收据与用户结果 |
| --- | --- |
| 准备/派发前事务失败 | 不写 OMP；保留草稿及已落盘记录，报告实际失败阶段 |
| 准确关联的 prompt success，且 ACK 与消费标记持久成功 | acknowledged（调用已确认）；只腾空仍对应 A 的输入，A 以可查看、复制的发送记录保留；不宣告 accepted 或完成 |
| 同 ID 后续错误 | 保留已持久 ACK 与原文，独立记录失败；不能仅凭异步错误判断接受前/后失败，不被迟到 success 覆盖 |
| 明确且有据的接受前拒绝 | 标注 rejected；原文可恢复，已经发生的调用确认事实不删除 |
| 尚未持久确认 ACK 就断链、超时、进程故障或 ACK 事务失败 | unknown；不清稿、不重发。库不可写时，重启将残留 dispatching 解释为 unknown |
| ACK 持久化后执行/原生持久化失败或断链 | 不撤销 acknowledged/消费标记；独立显示失败或执行结果未知，原文继续保留 |
| 重启发现 prepared | 仅展示准备记录；用户明确继续后重新校验，不自动派发 |
| 重启发现 dispatching/unknown | 不重发；只读核对，不能凭同文、队列长度或时间猜测确认 |

收据保存冻结内容、原草稿 revision、目标身份、原生命令/requestId、观察实例、判据版本和时间。Host 的唯一请求关联表按命令生命周期有界保留，不因首次 success 立即丢弃；保留有限迟到识别，超出窗口报告关联缺口，不无限保留活跃请求。重复 submissionId 只返回已知状态。

业务 `accepted` 与调用 `acknowledged` 不混称。普通流没有可靠逐提交关联时只归属 Thread/会话；user message、agent_start/agent_end 或助手正文不能单独证明某次提交业务接受。S2 保留官方普通 prompt 语义，不插入隐藏 ID，不 fork；冻结发送记录不自动回收，不依赖原生历史已保存 A。S1 的本地保存核对不能解除 OMP unknown。

### 4. 调用确认 A 后的草稿处理

采用“持久消费标记 + 原保存写序列”交接：调用 ACK 收据与“对应稿已消费”的 revision 标记在同一事务更新，**ACK 事务不另行改正文或推进草稿 revision**。恢复投影只有在当前持久草稿 revision 仍等于已消费 revision 时才呈现空输入；原文仍由冻结提交保存。B 已落盘则 revision 不同，恢复 B；B 尚未落盘则原 CAS 基线没有被 Main 悄悄改变，仍由原保存序列落盘。

Renderer 仅在当前编辑序号仍对应 A 时清空编辑内容；B、后续 undo/redo 产生的新编辑及 IME 组合都保留。清理与普通编辑一样进入同一保存协调，阻止旧 A 的待保存快照在已消费后重新发布为新稿；未消费的新编辑不会因正文恰好相同被去重。通知丢失后可从持久收据/草稿标记恢复相同结论，消费应用需按 submissionId/revision 幂等，不重复发送。恢复接口必须返回有效草稿及消费关联，S1 的保存核对也须识别该合法转换，不能把原始数据库正文直接当作仍未发送的草稿。Main 不能绕过输入协调独自改 revision，再让旧控制器继续盲写。

失败/unknown 的原文以只读提交记录保留，并可复制；不得强行回填覆盖新草稿。显式重新发送属于新 submissionId、关联原提交并提示可能重复；完整未知提交核对/重发 GUI 在 S3，S2 不用普通“重试”按钮偷渡自动重发。

### 5. Runtime、配置、信任与历史

- 正式构建携带固定兼容 OMP；初始证据基线为 v18.3.0 / commit `62bc57be1b03ef0802a33cf7f5f530e534527531`。开发与打包均走受管理资源解析；发布资源有版本、来源与校验记录，不依赖本机全局 omp、临时绝对路径或可写安装包目录。
- App 数据仍在 App 可写数据目录；原生配置、凭据、会话及记忆遵循 OMP 上下文与写入所有权。配置读取与执行使用一致 configContextId/cwd/profile/environment；不自动复制或覆盖个人配置，不执行 shell startup 文件补环境。开发验收使用隔离根，用户试用复用其明确选择的原生上下文。
- 新目录默认仅浏览。用户显式允许执行后才启动会加载项目配置/扩展的原生链路；允许执行不等于立即发送草稿。Main 持久信任并在启动/派发时复核真实目录，不通过父目录信任授权所有子项目。
- 界面说明“项目执行”与“App 文件访问”独立，OMP 可访问当前 OS 用户可访问的其他资源，绝不称为项目目录沙箱。撤销立即阻止新操作；已有工作未停止前不能显示“已降级为仅浏览”。完整运行中停止/撤销协调按 S3 实施，不能用 S2 的信任开关虚报已终止。
- 已有可用配置可继续；缺失/不完整/不兼容/不可读分别报因，保留草稿和只读入口。展示模型不等于认证请求可用，不发送计费请求作无提示配置探针。两条新增认证和完整设置 GUI 留 M2。
- 同一原生会话 App 内单拥有者；首次创建由本 Thread 管理。第二次提交正常复用同一存活 OMP/原生会话，不创建新会话。进程失效后不偷偷换新会话实现“继续”；只读查看和明确中断，执行恢复按 S3 的占用证据准入。
- 只读历史读取与执行启动分离，限定本 Thread 已绑定、受管理且经路径校验的原生引用。可复用固定版本原生 loader/流式访问思路；不能调用创建执行会话的入口当历史查询。处理写入中的不完整尾行、缺失、来源改变和不支持版本；不写回原生文件、不默认迁移。
- 原生 get_messages_page 在 streaming/compacting 时可能 busy，且读取当前上下文；busy 不能显示成无历史，当前上下文也不是完整持久记录。S2 建立只读读取和有界实时阅读路径，完整忙碌重连/压缩/分支恢复矩阵仍归 S3/S5。

### 6. 阅读与正式界面

- 沿用 Streamdown + Shiki 单一阅读入口，按本次真实事件接入文字/代码、用户输入、必要工具开始/结果/错误和执行状态；可选中复制 Markdown/代码。未知事件保留受限说明，工具结果的错误/截断/缺失不被模型总结掩盖。不新增文件/Diff 工作台或完整子 Agent 面板。
- Host 维护有界投影，以 generation、单调 seq 和 snapshot watermark 同步；先订阅缓冲，再快照，再接水位后增量。缺号重同步，旧代次丢弃。文字按 block 合并，工具/交互/终态前刷新；缓存与必要补充存储沿用基础契约预算，超限有可见缺口，不无限缓存或堵住 stdout。
- 调用已确认、执行中、待交互、结束和失败分开显示。原生要求交互时不能假装已结束或静默代答；完整回答控件属于 S3，S2 给出真实待交互与阶段限制，主验收样本不依赖该控件。
- 发送快捷键沿用既定方向：默认 Enter 发送、Shift+Enter 换行；可切换 Enter 换行/⌘Enter 发送；展开编辑区临时采用后一模式，收起恢复偏好。IME 候选确认优先，不因发送/展开重建编辑器或重置选区、撤销。将来 @ 候选同样优先于发送，本轮不实现 @ 检索。
- URL 保留原目标，本地识别已定网站/通用链接图标，经自有 Icon Layer；不自动抓网页或 favicon。Markdown 源文仍可编辑，不前置所见即所得排版、多媒体与富格式转换。
- 复用 S1 token、浅/深主题、normal/compact 单一入口、Base UI、自有组件和设计 lint。正式 GUI 实现时使用设计系统 skill，不预铺完整组件库。
- 关窗/刷新不能结束 OMP 或重发输入，Host 继续消费输出，新窗口获取当前投影。S2 接入必须保护既有关闭行为；真正退出先持久化草稿/收据并识别活动工作，不能把 S1 “草稿已保存”直接当成可结束运行任务。完整等待/停止后退出/故障恢复体验归 S3，S2 交付前至少验证活动任务不会被无提示销毁，并明确尚不支持的控制操作。

### 7. 诊断与错误

扩展 S1 已有诊断设施，真实链路沿用同一 traceId，记录 submissionId、Thread、实例/代次、阶段、原生 requestId 和构建 ID。preload confirmed 仅证明已核验桥接响应，不冒称 OMP 接受或 DOM 呈现。没有可靠提交关联的原生流只关联会话，并记录关联粒度。

prepared/dispatching/ACK 观察/acknowledged 持久化/输入交接分别可追踪；错误保持 code、观察位置、报告方、恢复拥有者和未知归因。凭据、正文、SQL、原始 stdout/stderr 不进常规日志。诊断写失败不改变业务结果；业务收据写失败必须停止推进或保留 unknown。不中途增加通用观测平台。

| T1 普通提交交接（方案已定） | prompt success 是调用 ACK，后续可同 ID 错误；普通事件无逐提交身份。额外业务接受关联未闭合。 | 用户已确认保留官方 OMP。直接实现关联 ACK + 持久发送记录 + 消费标记，测试迟到错误、落盘失败、断链及 B 保护；不再为业务接受另搭探针。 | 票 02/05 的合同测试与集成，不是待研究前置 |
| T2 只读历史 | 原生有无 writer 的只读 loader 与流式 entry visitor；涉及 Bun API，直接导入 Electron Node 并非已证实。read-only 全量 loader 不等于有界分页。 | 在正式接入中选择受限只读解析或可随包的原生读取桥接，核对 schema、leaf/来源、字节范围/游标及尾行处理；验证不创建 Agent/不加载扩展。无需重测“能打开 Runtime”。 | S2 只读历史集成通过；复杂运行中补页/压缩/恢复仍 S3 |
| T3 队列消费控制 | RPC 只有排队与消费模式，没有完整逐项管理/暂停接口。内部有 before-dequeue hook、claim/preparation、replaceQueues 等能力，但不是已验证 GUI 合同。 | 保留官方 Runtime 接入边界；到 S3/M2 核对能否在消费前持有原生条目、独立维护停止/编辑阻止原因。只在这一未知会迫使更换架构时做最小竞争实验，否则到 S3/M2 验证，不提前造队列 GUI。 | 适配选型的兼容判断；完整行为分别在 S3/M2 |
| T4 占用与恢复 | 文件 publish lock 可保护写入，不足以证明整个会话只有一个执行者；既有 single-writer 注释不是跨 CLI 互斥实测。 | S2 使用 App 管理的新会话/同一存活实例；仅浏览恢复不要求启动。S3 前核对恢复单写，不能确认则只读、禁止强占。 | 进程重启后的追加，非正常两次提交 |

不得把调用确认冒充业务接受，或把首次 prompt 偷换为 follow_up：它虽在入队之后返回命令成功，但源码的闲时消费需要合适的已有上下文尾部，新空会话并不因此启动第一轮，且 slash/预处理语义不同。也不得用隐藏提示词、文本匹配或伪造原生字段制造接受身份。S2 使用官方 RPC，不依赖额外接受薄适配；后续队列能力仍按其实际范围核对。

## Testing Decisions

### 测试边界

优先在功能对外边界测试：以提交意图、持久存储结果、原生适配事件作为输入，观察派发次数、收据、恢复后的草稿及显示投影。不通过测试内部私有字段来“证明”实现。已有 DraftController/存储/Main/preload/Renderer model 测试是先例；沿用可控 SavePort、真实临时 SQLite 和可替换原生 transport，不为一套测试强行跨越真实持久化与外部进程两种故障边界。

功能/修复先写暴露行为缺口的失败测试，最小实现后转绿，再按需重构。纯规格不运行产品测试来虚报 S2 验收。默认 Vitest 等自动验证；Computer use 只补自动化难以替代的原生/视觉证据，每次说明目的。旧测试通过不代表新增链路通过。

### 必需行为样本

| 编号 | 行为与结果 | 证据层 |
| --- | --- | --- |
| A1 | 未信任时不 spawn、不加载项目扩展；信任后启动时重新检查目录，路径失效不回退 | 准入无头测试 + 隔离项目 sentinel 集成 |
| A2 | prepared/dispatching 写失败均零派发；同 submissionId 重入只派发一次；迁移保留 S1 草稿/信任默认值 | 提交协调 + 真实临时 SQLite |
| A3 | 捕获 A 后等待保存时编辑 B，冻结仍为 A；A 调用确认时分别覆盖 B 已保存/B 未保存/通知丢失/IME，重开不丢 B，后续正常保存无伪冲突 | 输入–收据组合边界，TDD；DOM 集成补编辑应用 |
| A4 | success 后同 ID 错误、ACK 持久化后执行失败、断链、ACK 落盘失败、旧代次与超时迟到；状态不倒退、不误清、不重发 | 适配合同测试 + 定向真实 OMP 样本；固定官方 RPC，无额外接受通路前置 |

| A6 | UTF-8 跨块、JSONL 多行、v2 分片缺失/交错/超限；4 MiB 可保存正文可能因编码后帧限制不能发送，原文不丢 | transport/预检边界 |
| A7 | 原生流与快照交错、重复/缺号/旧代次；工具/终态前刷新；输出有界、缺口真实，不靠全量缓存在内存 | Host 投影 + Renderer 订阅 |
| A8 | 不启动 OMP 的历史读取；进行中尾行、缺失/不兼容、当前上下文和持久历史不混称；模型 Markdown/URL 不获得执行权 | 只读 reader fixtures + 显示边界 |
| A9 | 包内受管理 Runtime、可写原生/App 数据位置、一致配置上下文；移动到含空格路径仍完成真实回合；缺配置/资源不可读明确失败 | 新正式 macOS 产物定向 smoke，不重复旧包矩阵 |
| A10 | 两次文字提交沿用同一 Thread/原生会话，真实流式结果可复制，第二轮能承接第一轮；trace 可追提交和结果，调用确认与结束分开 | 真实 OMP + 产品 GUI；先隔离确定性模型，用户已有真实配置另记试用证据 |
| A11 | 同时流式输出时输入/选择/复制可用，发送快捷键/展开/IME 正确；浅深主题与 normal/compact 传播；关窗不杀任务、不重发 | 自动交互 + 必要真实 GUI/用户试用，复用未受影响 S1 输入证据 |

不前置完整故障/性能/打包矩阵。受影响类型、业务测试、Biome、设计 lint/token/图标边界、构建必须通过；本切片新增流式负载做针对性输入/阅读检查，不冒称 4 MiB 编辑性能或 M2 全量长输出已验收。

### S2 完成与试用交接

按已定 ACK 合同完成集成，A1–A11 对应必要证据齐备，才可称 S2 工程交付。提供可识别构建、隔离数据启动方法和操作步骤：选项目 → 允许执行 → 发送 A → 阅读流式结果 → 同 Thread 第二次发送；预期状态、失败保稿、实际可用控制范围同时交代。首次真实模型验收使用明确选定的配置/隔离项目，不用个人凭据做后台探针。

区分确定性本地模型、真实供应商、正式 GUI、用户试用四类证据；用户未回复不能写成认可。旧 S1 试用包/数据不自动覆盖。S3 完整控制恢复、S4 文件/Diff 和 S5 组合验收未通过时，不宣称可日常自用。

- Windows/Linux 或干净机器/签名/公证的支持承诺；原生 macOS 独占新必需能力仍须单独对齐。
