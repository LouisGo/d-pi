## Problem Statement

用户希望通过熟悉的 GUI 完成日常 OMP 开发任务，获得自然的输入编辑、输出阅读与后续操作体验。首阶段需要一个能真实工作的桌面会话客户端，而不是再次设计 Agent Runtime，或仅演示一句话输入输出。

## Solution

在本机 macOS 上启动 Electron 应用，选定一个本地项目，沿用已安装 OMP 的模型配置与登录，完成单会话闭环：编辑需求 → OMP 读写文件／执行命令 → 查看流式输出和工具结果 → 回答问题、追加需求或停止 → 正常退出后恢复同一原生会话。

从第一版起由 utility process 承载 SessionHost。开发模式与本地 macOS 应用构建都必须接入真实 OMP，并从 Finder 启动构建产物验证资源路径；签名、分发和其他平台留到发布阶段。

## User Stories

1. 作为开发者，我希望选择一个本地项目并看到当前项目位置，以便明确 OMP 在哪里工作。
2. 作为开发者，我希望应用使用本机 OMP 和既有模型配置／登录，以便开始工作而不重复配置一套 Agent。
3. 作为开发者，我希望启动失败时看到可行动的原因并能重试，以便区分缺少可执行文件、配置问题与连接失败。
4. 作为开发者，我希望在多行输入框中选择、复制、粘贴、移动光标、撤销和重做，以便完整表达需求。
5. 作为开发者，我希望输入法组合输入不误触发送，以便自然输入中文。
6. 作为开发者，我希望发送失败或结果不明时保留可找回的输入，以便不丢失需求、不无意重复执行。
7. 作为开发者，我希望连续阅读 OMP 的回答和工具状态，以便知道任务正在推进还是等待我参与。
8. 作为开发者，我希望展开工具卡片查看参数、输出和错误，并能复制文字，以便理解执行结果并补充要求。
9. 作为开发者，我希望阅读旧输出时不被新内容强行拉回底部，并能主动回到最新内容，以便查看过程。
10. 作为开发者，我希望直接回答 OMP 的基础选择、确认和文本输入请求，以便完成任务而不退回 TUI。
11. 作为开发者，我希望停止执行后看到实际终止结果，以便不会把按钮点击误认为工具已停止。
12. 作为开发者，我希望一轮结束后继续发送需求，以便在同一 OMP 会话中迭代。
13. 作为开发者，我希望刷新窗口后接回已有输出和待回答交互，以便刷新不会重新执行任务。
14. 作为开发者，我希望正常退出后重新打开并继续原生会话，以便保留已完成的工作上下文。
15. 作为开发者，我希望异常退出后明确知道结果是否确定，并自行决定恢复后的下一步，以便避免自动重发有副作用的操作。

## Implementation Decisions

### 产品边界与所有权

- 保留已确定方向：OMP 专用桌面会话客户端；完整 OMP 拥有 Agent 执行、工具、配置、上下文及原生会话持久化。客户端不重建权限引擎、工具执行器或会话文件格式。
- 本里程碑以一个窗口、一个项目和一个活动会话为边界。正常恢复最近一次已持久化会话即可，不建设跨项目会话库。退出后恢复与窗口刷新重连是不同动作。
- 正式运行沿用本机配置及登录。缺少模型／登录时解释启动失败并指向现有 OMP 配置入口；不建设 GUI 登录和模型配置编辑器。
- 内置工具由 OMP 执行，未知工具名称使用通用卡片显示。自定义 TUI 渲染不在兼容承诺内，不为了展示而替换工具或默许确认请求。
- 按 V1 已定技术栈使用 React、TypeScript、Zustand、TanStack Query、Tailwind CSS、shadcn/ui、Zod、electron-vite、pnpm、electron-builder。保持单应用结构，首阶段不预建后续功能目录或重型编辑器。

### 进程与通信

- Main 管窗口、项目目录选择、可信连接建立、SessionHost 生命周期和应用退出。SessionHost 在 utility process 内管理 OMP 子进程、stdio RPC、请求关联、会话镜像、待回答交互和订阅。
- Renderer 管输入编辑、草稿、卡片、选择与滚动；preload 暴露受限接口。主业务数据使用 Renderer/preload 与 SessionHost 之间的 MessagePort，Main 不逐条转发输出。
- 以本机实测 OMP 18.3.0 为初始兼容基线；正式日常连接使用 `--mode rpc-ui`，以接住内置 `ask` 和工具审批。启动记录实际版本、等待 ready、按宣告能力协商协议；不声称兼容全部历史或未来版本。无法满足必要能力时给出明确错误。
- 使用独立 OMP 进程及 stdio RPC，不直接将 Bun SDK 放入 Node utility process。协议接收必须处理跨 stdout chunk 的 JSONL 行与 UTF-8 字节边界，并按 v2 的序号、长度和大小限制重组大帧。超限或协议错误终止当前不可信连接并说明原因，不展示悄悄截断的成功结果。
- 窗口来源、允许操作及参数在边界校验。来自模型的 Markdown／工具内容按不可信内容渲染；不暴露任意 Electron 或 Node API。

### 首版接口及状态契约

- 界面能力只需：连接项目／恢复会话、订阅当前状态、提交 prompt、停止当前执行、回答指定交互、请求重新同步。项目目录和可执行路径通过受控宿主流程传入，不给渲染内容任意 RPC 权限。
- 对请求分别表达提交中、已接受、明确拒绝及结果不明。请求 ID 用于关联，接受响应不能清除整个执行状态；同 ID 后续调度失败也必须显示。断连时不自动重发 prompt。
- 会话展示区分空闲、运行、停止中、等待用户以及连接中断后的最后已知状态。工具失败不自动等于整个会话失败；`agent_end.isTerminal === false` 不表示最终结束。
- 阶段 1 即支持：空闲时正常发送；运行时默认以 `prompt.streamingBehavior: "followUp"` 排队追加，独立干预入口使用 `"steer"`。Host 不自建调度或自动重发。界面先显示提交中、被 OMP 接受并待处理；只有对应需求出现在 OMP 的用户消息事件中，才标为开始处理。`get_state.queuedMessageCount` 是总量核对，不含逐项身份；若断连使单项归属无法确认，标为结果不明，不用计数推定某项已处理。
- 在 OMP 18.3.0 的受控模型实验中，默认两条 follow-up 依次进入后续模型请求；同轮提交的 steer 先于两条 follow-up 进入下一次请求。steer 在当前模型请求被等待时可触发中断路径；这不保证已发生的工具副作用会回滚。协议没有被本规格依赖的清空原生队列命令。
- SessionHost 给每次实例分配连接世代，给镜像更新分配递增序号。订阅先取得与后续增量衔接的快照；发现序号缺口或旧世代更新时重同步，不拼接不同实例的状态。
- 连续文本增量在 Host 短时间合并后发送；工具、交互和终态事件之前刷新待发送文本，保持观察顺序。订阅积压有界，慢消费者改为重新取快照，不能无限缓存或每个 token 发送整段历史。
- 更新局限于受影响消息／工具；完成消息再做完整 Markdown 处理即可。首版不以未经测量的性能数字或框架选择作为流畅保证。

### 输入、工具与交互

- 支持多行纯文本需求和系统常规编辑操作；发送有明确按钮及不会打断输入法组合的快捷键。发送前保留输入副本；未提交草稿与已提交但结果不明的输入分开保存，支持窗口刷新与正常退出后找回。
- 工具卡片展示名称、进行／结束状态、参数、输出或错误；折叠长内容且可展开和复制，不能静默丢失结果。首版无需专属 diff 编辑器或交互式终端。
- `rpc-ui` 内置 `ask` 和工具审批，以及基础 `select / confirm / input / editor`，均经 `extension_ui_request` 映射为可操作控件；用户可明确批准、拒绝或取消。按当前会话、Host 世代和请求 ID 关联回答，防重复提交；在 timeout、cancel 或断连后禁用过期回答。Renderer 刷新后仍展示 Host 持有的有效待回答交互。
- `notify / setStatus / setWidget` 可降级成可读文本；不支持的交互应明确报告并在协议允许时取消，不自动同意，也不永久留在看似运行的状态。

### 退出、停止与恢复

- “停止当前执行”调用 Agent `abort`，等待当前执行终态；RPC `abort_bash` 是另一命令。OMP 18.3.0 实测：只排了 follow-up 时，`abort` 后 `queuedMessageCount` 仍为 2，下一次正常 prompt 后两条再按序处理；同时有 steer 时，`abort` 后队列可能立即继续。因此停止按钮不得承诺清空队列；界面显示仍待处理数和可能继续的状态。确认前显示停止中；超时显示结果不明，不宣称已撤销外部副作用。
- 刷新 Renderer 保留 Main、Host 和 OMP；重连依靠镜像快照，不重新提交 prompt。
- 关闭最后窗口保留 Main、Host 和 OMP，任务继续；从 Dock 重新打开时同步已有会话。Cmd+Q／退出菜单才真正退出；有未完成工作时提供等待完成后退出、停止后退出、取消退出。待回答交互允许重新进入处理，排队需求纳入未完成工作。等待退出需保持应用存活并可回到待回答界面；停止后退出先请求 Agent 停止，再终止受管理执行进程，不能等同于单发 `abort` 后任由队列继续。正常空闲退出关闭 stdin 并持续消费 stdout，设置有界退出等待。异常或超时由宿主清理受管理 OMP 和其受管理后代；不能仅凭 Host 退出假定所有工具已停止。独立托管、已由 OMP 转交的后台服务不伪装成已清理，必须报告仍未知的状态。
- OMP 或 Host 崩溃后保留最后已知输出并标为中断；完成旧进程清理后，由用户显式恢复已持久化原生会话。不承诺 attach 回原 stdio 进程、不自动续跑或重放结果不明的命令。
- 原生恢复由 OMP 完成，GUI 只保留项目和最近恢复目标等客户端元数据。核实会话文件已实际落盘后才记为可恢复目标；新会话在助手消息产生前可能尚未落盘。未持久化输入由客户端草稿／发送记录承接，不伪造 OMP 历史。
- 不允许本应用同时为同一会话启动两个写入进程；碰到 OMP 的锁或会话占用错误时提示，不绕开原生保护。

## Testing Decisions

用户已确认：优先在真实客户端边界测试可观察行为，不测试内部函数调用次数。仓库目前没有应用测试先例；已有原型验证了真实 Electron／OMP 边界，但没有可视 GUI。正式验收以完整窗口为最高测试入口，故障注入只在 OMP 传输边界替换数据，避免另造多套测试接口。

| 场景 | 操作与通过条件 |
| --- | --- |
| 启动与配置 | 在本机可用配置下进入会话；分别指定无效可执行路径、不可用配置，看到明确错误且可重试，草稿不丢失。 |
| 真实开发闭环 | 在一次性测试项目中要求 OMP 读文件、修改一个确定内容、执行检查命令；核对磁盘变化、命令实际结果和 GUI 工具卡片，再追加一轮需求。必须使用真实模型完成，不能以固定响应原型替代。 |
| 输入与阅读 | 手动或 UI 自动化核对中文组合输入、多行编辑、选区、剪贴板、撤销／重做；输出持续到来时能够编辑草稿，阅读旧内容不被抢滚动。 |
| 内置交互 | 真实 `rpc-ui` 内置 `ask` 与工具审批在 GUI 完成批准、拒绝、取消；OMP 工具结果与磁盘／命令副作用相符。补测基础 `select / confirm / input / editor` 的刷新、重复点击和过期回答。 |
| 正常停止 | 真实 Agent 执行一个可观察的长命令时停止；验证 Agent 进入终态、受管理测试命令不再运行，GUI 不提前宣布停止。另测 RPC bash 的独立取消。 |
| 执行中输入 | 执行期间默认发送进入 OMP 后续队列；独立干预入口走 steer。验证接收与处理状态、顺序、停止后仍存的队列及断连，不强制杀进程、不重复提交。 |
| 关闭与退出 | 任务执行中关窗，确认进程持续；Dock 重开接回同一会话。分别验证真正退出时的等待、停止和取消，以及存在排队需求／待回答交互的情况；停止后退出不再消费排队需求。 |
| 窗口刷新 | 输出期间刷新，OMP PID 与会话身份不变；恢复后内容与 Host 镜像一致，无缺段、重复消息或重复 prompt。 |
| 原生恢复 | 完成有助手输出的真实任务，正常退出再打开；会话 ID、历史和追加上下文保持一致。另测尚未落盘的新会话：草稿可找回，不伪报“已恢复”。 |
| 进程故障 | 在一次性测试项目执行可追踪长命令，分别让 OMP、Host 异常退出；GUI 标记中断，Main 完成受管理进程树清理或准确报告失败，不自动重发。记录 PID 和最终存活状态作为证据。 |
| 协议边界 | 可控数据拆开 JSONL、跨 UTF-8 字节、大于单帧的 v2 输出；验证合法数据完整呈现，乱序、超限、截断明确失败。增量序号缺口触发重同步。 |
| 发送不确定 | 分别在已接受响应之前和之后断连；输入可找回且不自动重复执行，用户看得出明确失败与结果不明。 |
| 持续输出 | 输入快速更新与长工具输出，核对停止和输入仍能响应、订阅积压受限、终态前文本不丢失。记录场景、版本和观察结果；如失败再做针对性性能剖析。 |

完成条件：开发模式和本地构建产物都能从可见 GUI 接入真实 OMP；上述影响正确性的场景通过并留下结果；用户能在 GUI 完成真实单会话开发闭环。仅类型检查、构建通过或固定模型原型成功均不足以关闭里程碑。凭据不可用等外部阻碍应记录为未完成验收，不能改用模拟结果宣称完成。

## Out of Scope

- 多项目切换、多会话并发、复杂会话分支、GUI/TUI 同时写一个会话。
- 完整 Codex App 复刻、通用 Agent Workbench、跨 Runtime 或跨框架模型。
- 图片附件、富文本需求编辑、专属 diff 编辑器、文件树、交互式终端和工具插件市场。
- 自定义 TUI 界面的完整兼容；GUI 内配置模型、登录、安装和更新 OMP。
- 自建工具、权限策略、Agent 调度、会话数据库或从 GUI 消息反向重建模型上下文。
- 托盘专属交互、无缝进程故障接管、自动任务重放。
- 对外签名、公证、自动更新、跨平台认证和无具体瓶颈依据的性能平台；本地 macOS 应用构建与 Finder 启动属于本阶段。
