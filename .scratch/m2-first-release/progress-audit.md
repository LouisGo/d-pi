## 当前包到底能做什么

可从“新会话”创建独立 Thread，选择模型/档位并应用；新项目先允许项目执行，然后“启动 OMP”，就绪后发送文字并阅读回复。切换项目/Thread 保留草稿和独立后台资源，Renderer 刷新接回现存实例。真正退出后的旧 Thread 当前只读，不承诺继续旧执行。已有原生凭据/模型目录已经由 m2.8 复用；无需独立安装 CLI。

对**同一个 m2.8 交付包**重新运行 `validation/m2/package.mjs`，使用隔离 HOME/App 数据/项目/Git/原生配置及 localhost 模型，不使用个人凭据或真实付费请求。[结果](evidence/m2.8-progress-result.json)确认 clean 构建身份、8 个场景全部通过和两条本地供应商请求：发送/最终回复、双 OMP 并行、模型/档位及身份隔离、编辑选区/撤销、Renderer 重连无重发、冷只读/独立新建出口。见 [日志](evidence/m2.8-progress-package.txt)、[并行闭环截图](evidence/m2.8-progress-parallel.png)、[冷恢复截图](evidence/m2.8-progress-cold.png)。这是包内真实 OMP 与 Electron 的确定性闭环，不是实际 GPT 网络/账户生成验收。

Computer use 在用户实际 m2.8 中确认上述只读/禁用状态、缺少记录、Shift+Enter 失效，并确认独立新 Thread 能打开九模型菜单。保留原 hello 草稿；未启动个人配置的 OMP、未向真实供应商发送。检查时创建的一条空白独立 Thread 保留，没有删除用户数据。

## 为什么此前验证没有拦住

既有包内 harness 能从已知按钮找到新会话，因此证明入口存在及原生闭环能执行，却没有证明用户从冷恢复首页能发现入口/理解禁用原因。已有输入用例覆盖文字、粘贴、撤销及 Enter/IME，没有直接覆盖实际 Shift+Enter 换行。模型验证覆盖应用后的原生效果及 Thread 隔离，没有检查面板打开时当前模型/档位回填。这些是验收路径缺口；CLI 历史发现则此前没有进入该候选交付范围，不能混作测试漏检。

交接标题“反复使用的主流程”和 01 “自然新建出口”的完成表述对可发现性过于乐观；总体 M2 in-progress/pending 是准确的，但不能抵消局部已承诺体验未兑现。保留历史快照，追加本次纠正，不改产品要求迁就实现。
