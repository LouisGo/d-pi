## 反复使用的主流程

1. 解压并打开 `d-pi.app`。已有原生配置会复用；“配置与认证”可查看当前目录/profile 和两条新增认证状态。没有个人配置时，由用户登录 OpenAI 账户（系统浏览器、原生挑战/授权码/取消）或填写 DeepSeek API key。DeepSeek 原生 GET 模型列表校验后保存，失败保留旧凭据；不把 key 写入 App 数据或日志。
2. 打开项目目录。“更换模型/档位”读取原生目录，搜索/选择可用模型，再“应用到当前会话”。未认证/禁用原因可查看；已有自定义模型仍可复用。这里是当前 Thread 主模型，未声称完成子 Agent 覆盖。
3. 新目录先“允许项目执行”，再“启动 OMP”。允许的是当前 OS 用户权限下的原生执行，不是目录沙箱。发送后可观察原生输出、工具和待答交互；“提交原文”保留 App 收据及冻结原文。
4. 同项目“新会话”，或再次“打开项目”选择另一目录；左侧切换已有会话。切换先保存草稿，不停止后台 OMP；各 Thread 的消息、模型、草稿和原生身份独立。
5. 输入保持在工作区底部；会话、只读文件/Diff、提交原文及历史分别滚动/切换。展开/收起不重建编辑器。普通结构粘贴转可编辑 Markdown，一次撤销/重做；编辑菜单提供纯文本粘贴入口。附件粘贴当前明确阻止整项并保留原草稿。
6. Renderer 刷新接回现存实例，不重发。真正退出/崩溃后旧原生会话当前保持只读，草稿保留；显式“新会话”创建独立执行，不冒充恢复旧执行。unknown 收据不自动重发。
