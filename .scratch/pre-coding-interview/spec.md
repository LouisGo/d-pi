# 编码前用户交付访谈

## 目标与范围

2026-09-27 用户要求：从用户能得到什么出发，理解产品方向及核心架构，查漏补缺、发散检验盲点，并对齐用户与现存文档的理解。聊清楚后结束，接近收敛时提前提醒；过程中的反问仍围绕这一目标推进。

本次交付为访谈及文档共识，不启动产品编码。现有决定继续有效；新答复确实改变方向时，记录依据与取代关系并同步相应规格。仅在出现已解决的新术语或重大架构取舍时更新 CONTEXT 或 ADR，不把待答问题写成决定。

## 访谈路线

1. 用具体日常工作明确产品价值、首版成功与不可接受的体验。
2. 沿输入、执行、观察、检查成果、继续工作的链路检验用户预期。
3. 通过多任务、故障、恢复及权限场景解释并检验架构分工。
4. 区分开工前必须对齐的产品选择、随切片验证的技术未知、后续能力。

每轮少量问题，依据回答调整；每个主题核对用户预期、文档现状、差距和处理归属。最终收敛依据为：核心场景和边界已对齐，重要取舍明确，近期切片的阻塞问题均有答案或验证路径，用户没有尚未澄清的关键疑问。不得以回答次数或文档数量判定完成。

## 收束结论（2026-09-27）

用户最终确认 OMP / d-pi 后台 / GUI 的职责分工。访谈结束，产品方向、近期范围和关键交互已具备推进近期切片的共识；这不是技术验证全部通过，也不是本轮开始产品实现的授权。下方各轮保留当时的提议、误读及纠正；历史“待确认”以随后答复和本节为准，不作为仍然开放的问题重复追问。

### 已对齐

- 以 OMP 为执行内核，用 GUI 提升输入、阅读与掌控感；最终核心体验覆盖 TUI，分阶段交付。
- M2 包含桌面编辑手感、附件预览/重排、可靠 @ 引用、链接识别与图标、完整队列管理，以及合理的子 Agent 默认配置和当前 Thread 的后续模型/档位覆盖。
- 停止中断当前执行并暂缓后续队列，内容保留，明确继续才恢复；队列编辑保留独立的消费暂缓语义。
- 后台待答/失败及时提醒，完成默认静默标记，不抢焦点；关窗不等于退出，工作与队列编辑保留。
- worktree 原生机制优先复用，实际目录身份可见，已知跨 Thread 冲突在副作用前阻止并提醒；创建/迁移/清理阶段不提前。
- 初期先打通关键链路，不开展自用迁入；时机合适再渐进评估。每段可操作体验交给用户试用，内部实现步骤不逐项等待批准。
- OMP 拥有模型/工具/子 Agent/真实队列及原生历史；d-pi 后台负责宿主协调、草稿/收据、恢复和入口适配；GUI 消费真实状态并提供交互，不另建执行内核。

### 实施前及随切片验证

详细责任与门槛以[近期计划](../development-foundation/spec.md)和[基础契约](../../docs/architecture/foundation-contracts.md)为准。优先验证会改变对应切片路线的未知，不要求所有功能 G1 同时完成：

- M1：持久化/输入最小链路；实际接受证据、提交未知不重发；停止与后续队列暂缓/继续；占用、关窗和故障恢复。
- M2 对应功能：逐项队列身份/编辑/删除/重排及消费竞争；Thread 子 Agent 配置隔离、档位优先级和真实调用；认证桥接、附件实际输入、长输出与真实 GUI 性能。
- 若接入只能通过重大所有权改变、长期 fork 或削减已确认功能实现，带具体证据重新对齐；不能以纯 GUI 状态假装支持，也不能因薄适配尚未验证直接判定不可行。

### 明确保留的后续设计

透明展示的具体内容/层次和吞吐口径另设专题，在相关阅读切片细化；不作为所有基础工作的全局阻塞。图片编辑、输入框直接呈现 Markdown 样式、工作分区、子 Agent 自动降档/确认倒计时、worktree 管理等按已定后续范围推进。智能完成推荐仍为候选。自用迁入没有固定日期或里程碑承诺。

## 访谈记录

### 第一轮：首版的日常使用价值（已回答）

围绕一个真实开发任务，明确用户希望首先迁入 d-pi 的工作，以及虽然功能存在仍会导致其放弃使用的体验。提问不重新表决已确认范围，也不自行删减 M2。

用户说明：现有 Codex App 已经足够好用，开发 d-pi 的动机是能够自主改进 GUI，在 OMP 内核之上持续提供原产品没有的交互和工作管理能力。完整承接 OMP TUI 的能力与优势、极致输入输出、流式过程的掌控感和透明呈现是价值核心。

放弃使用的条件：Bug 频发、卡顿与毛糙、莫名错误带来的不可靠感，以及已有 OMP 能力在 GUI 中退化或输入输出体验不佳。上述原则补充现有需求，不代表已有实现通过。

用户举例的探索方向：多子 Agent 并行时指定模型/思考程度及管理；token/s 动态指针可视化；超越项目与 Thread 的工作组织和智能分类标签。原话中的“绘画”结合上下文疑似“会话”，尚未据此定义图像生成或新的工作实体。例子不自动成为 M2 承诺。

发现的待对齐点：

- D-27 当前只确认按 Agent 定义设置默认模型/档位、后续 spawn 生效；用户所说管理是否包含逐次任务分工、直接调度和运行中控制，需用场景厘清。
- D-01/D-26 允许渐进覆盖，M2 尚不包含全部 TUI 能力；“不能退化”是指已接入路径的质量底线，还是转为日常使用所需的完整覆盖门槛，需明确。
- 吞吐可视化需要区分原生 token 证据与估算，指标定义和接入能力未核实。

尚未判定达到开工条件。下一轮先厘清子 Agent 掌控边界与渐进交付的使用门槛，工作组织和透明呈现细节保留后续追问。

### 第二轮：默认配置与渐进覆盖（已回答）

- 多 Agent 初期应提供合理默认策略，不让用户承担大量逐次分配决策；同时允许在控制面板/设置或会话中设置后续子 Agent 的模型和思考档位，期望支持跨模型及供应商。
- Astra/sol 的映射及 step 降档只是用户举例，未确定通用排序或算法。完整管理体验留待后续，不要求现在设计运行实例的全部控制。
- 最终核心体验应为 TUI 的超集；早期围绕核心体验取舍，部分仅适合 TUI 的工作可以不接入 GUI。未指定任何具体排除项。
- 已同步 D-01/D-27 与需求。M1/M2/M3 不变；用户说的“第一阶段”尚未映射到具体里程碑，不能自动将新策略纳入 M1/M2。

证据与未知：已有 OMP v18.3.0 隔离 Settings 实验表明外部配置能影响同一主会话后续 spawn 的模型/档位；启用 task.enableEffort 时主 Agent 的 effort 可覆盖默认档位。实验使用本地固定模型，不证明 GPT/DeepSeek 的真实跨供应商组合已经验收。智能默认策略、用户显式设置的约束程度及自然语言配置的作用范围仍需厘清。

后续继续追问用户显式选择与主 Agent 自主调整的关系、透明执行的具体阅读场景，再覆盖输入、工作组织、故障恢复及开工门槛。尚未收敛，不开始产品实现。

### 第三轮：配置调整确认与透明展示（已回答，部分细节保留）

用户期望：主 Agent 认为指定子 Agent 配置难以完成任务时，通过 confirm 或提问交互让用户确认调整；可设置倒计时，超时由系统代选。未指定超时动作、授权范围、配置作用域或持久性，也未将此机制扩展到其他权限交互。同步需求与 D-27 的补充记录，未宣称原生机制已支持。

透明的核心是避免在思考/压缩等慢响应阶段只给笼统状态，使用户误以为 Agent 没在工作；通过真实信息帮助理解执行与等待。token/s 是例子。用户明确将可见内容、GUI 与 TUI 的展示策略差异留到专门环节深入设计，本轮不展开完整方案。

工程判断：吞吐、活动证据与根因不是同一件事；没有流式 token 或没有新事件时，不能靠动画或虚构速率证明模型在正常执行。具体可观测性需核对原生事件和指标，未测内容保持未知。

后续专门设计议题（不视为已经完成）：

- 展示：原生可观测信息、默认/展开层次、流式阅读体验、等待/压缩/工具活动及 token/s 口径；比较 TUI 展示策略。
- 子 Agent：默认映射、用户覆盖、调整确认与超时策略、会话设置的范围、真实跨供应商路径；交付阶段仍需映射。
- 工作组织：用户提出的工作分区、分类与标签，尚未定义领域实体或影响执行边界。

访谈仍继续；详细设计可后置不等于产品问题已全部对齐。接下来转向输入主路径，并继续核对影响开工的边界。

### 第四轮：输入体验（已回答，图片调节范围待澄清）

用户以 TUI 和 Codex App 的使用痛点说明要求：图片/附件需要预览和可操作的内容承载；长短粘贴文本不能成为不可修改的块；支持顺畅的撤销重做、光标移动、快捷键选区和首尾定位；拖入/粘贴按 MIME 等信息处理；输入区上方显示多媒体预览，可点开查看并调整位置。@ 检索需支持 @message@List 等本身含 @ 的路径，并改善真实项目检索速度。

用户要求显式处理不同模型多模态能力及切换模型时的输入状态。按现有 D-29/D-30，将“状态机”理解为明确状态转换而非引入 XState；原有内容保护和发送前预检合同继续有效。分离编辑状态、附件准备、模型兼容性和提交状态，具体类型留给实现切片。

已将可验收要求集中写入基础方案的 Composer 章节，并在输入模块和决定登记引用。当前只记录用户对其他产品的使用体验，不宣称本轮复现了外部产品缺陷。

待澄清：图片“调节/调整位置”是否仅包含查看缩放和附件重排，还是包括裁剪、旋转、标注并发送修改后的图片；不能从模糊表达直接扩成完整图片编辑功能。其余既有引用/附件/发送要求不重复表决。

### 第五轮：图片处理与链接展示（图片范围已回答）

用户确认上一轮图片操作两个层级都需要：查看缩放/附件重排，以及发送前裁剪、旋转、画框/标注并发送处理后的图片。关闭第四轮范围问题，具体实施批次尚未确定。

新增链接展示要求：粘贴链接时快速识别预设网站，名单内以品牌图标（例如 GitHub）加链接展示，名单外以地球图标加链接展示。助手曾将“后面做”误读为后置链接图标增强；用户随后明确纠正，正确范围见第六轮，此前解释作废。

工程处理沿用 D-31：网站识别可本地解析，无需仅为图标访问链接；名单属于显示映射，不是权限信任名单，也未新增自动获取网页正文的要求。输入展示与实际交给模型的内容分开验收。

助手曾提议转向结果检查；用户随后要求继续输入体验，按该方向继续访谈。透明展示专题和新增能力的里程碑归属仍待收敛。


### 第六轮：纠正 Markdown 呈现的阶段理解

用户明确：一开始做方案、spec 和 ticket 就要写清楚对标 Codex App 的具体输入体验。允许后置的是整个输入框直接呈现 Markdown 样式，如 H1、H2 和表格；不是链接识别与网站图标。已纠正基础方案、需求、输入模块与决定登记中的错误表述，保留本记录说明误读与纠正关系。

继续讨论输入体验，不转去结果检查。Markdown 原文编辑与直接渲染样式区分；富内容粘贴的转换规则等未提及行为不从本次纠正中自动推导。尚未生成 ticket，后续拆票需引用这些具体体验与验收要求。

### 第七轮：富内容粘贴规则（已确认）

用户明确采纳建议：从网页或文档普通粘贴时，尽量保留标题、列表、表格等结构并转成可编辑 Markdown；同时提供“粘贴为纯文本”。已同步需求、Composer 方案和决定登记；不提前实现 Markdown 所见即所得排版，不承诺所有剪贴板来源均已支持。

继续输入话题。现有方案中的 Enter 发送/Shift+Enter 换行仍是助手建议，用户尚未明确选择；中文 IME 候选确认与 @ 候选选择不应误发送的合同继续有效。

### 第八轮：发送快捷键与展开编辑（已确认）

用户明确发送配置必须可切换，默认 Enter 发送/Shift+Enter 换行；点击放大输入区按钮后应自然切为 Enter 换行/⌘Enter 发送。关闭第七轮的快捷键待决项，已同步输入方案、需求、模块和决定登记。

工程细化：将用户偏好与展开状态分开，展开只临时覆盖生效模式，收起恢复原设置；界面提示当前发送快捷键，保持文字、附件、选区与撤销历史。IME/@ 候选优先于发送规则。具体放大布局未定，不为此引入全应用新状态机或改动普通发送排队语义。

### 第九轮：可视化与直接管理队列（已确认目标）

用户明确队列必须可视化，可以直接编辑某条排队内容、删除和调换顺序。不是仅展示排队状态，也不以“撤回到主输入框重新发送”替代直接编辑体验。已扩充 D-11、需求、基础契约与执行模块，并在开发准备中记录对应证据缺口。

本轮核对现有本地验证与合同：OMP 拥有原生队列，现有记录未证明逐项编辑/删除/重排可通过公开接口完成。本轮没有运行新原生实验或检查新上游源码，不能判断能力不存在。后续应核实原生队列身份、操作确认及与消费并发的边界；不自动改为 App 持久执行队列。具体交付阶段待总收敛。

下一问题：用户打开某条排队内容编辑时，是否期望暂缓该条消费；若当前执行在其保存前完成，怎样避免旧内容先被执行。该行为影响实际掌控感与原生适配要求，需要用户取舍。

### 第十轮：编辑队列条目时的消费策略（已确认）

用户采纳建议：进入编辑即暂缓该条消费，保存后按新内容继续，取消恢复原内容；当前执行不受影响，轮到编辑中条目时明确等待，不跳过执行后面的内容。第九轮消费策略问题关闭，已同步需求、D-11、基础契约与执行模块。

工程验收仍须核实执行侧暂缓证据、与原生消费竞争及编辑保存失败/断链恢复；不能仅锁住界面，也不能以视图卸载自动提交未保存内容。这些是对应队列管理切片的证据缺口，不代表用户仍未确定预期行为。

### 第十一轮：工作分区的交付时机（已确认后置）

用户明确工作分区一开始不做，属于后续增强。近期沿用项目与 Thread，不继续追问分区的组织/共享/协作语义，也不将其列为开工前置或提前建设基础设施。已同步需求与决定登记；最终探索方向保留。

当前访谈进度：定位、输入体验与队列控制已形成具体共识；透明展示专题、Markdown 样式直接呈现和工作分区按用户要求保留后续。尚需检查成果验收与继续工作的核心路径，并汇总本轮新增要求的近期范围及技术验证缺口，不能据此宣布访谈完成。

### 第十二轮：成果检查与下一步引导（方向已记录）

用户认为传统 Agent 将完成总结、修改内容放在模型回答中，不足以形成标准的功能/展示模块。期望结合任务判断最迫切的检查行为，默认展示其结果，并提供几项可点击的备选入口，涵盖 Diff、测试详情、运行页面和继续追问。具体设计未定，已在产品需求新增集中说明，并在决定登记和阅读模块建立引用。

工程建议待落实：任务相关的推荐与可追溯证据分开，不能把模型总结直接当成测试通过；既有结果的展示与新测试/服务启动区分。当前浏览器是后续能力，用户举例未自动改变阶段；不为此提前确定 Run 边界或新增执行引擎。
