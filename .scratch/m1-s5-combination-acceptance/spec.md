## 验收选择

基于[既有 S5 与 A1–A12](../development-foundation/spec.md#跨模块验收场景)，复用 S1–S4 的合同与边界回归，选择当前组合的新接缝：

| 组合 | 必须观察 | 证据方式 |
| --- | --- | --- |
| A1/A4/A9 | 稳定 Thread/目录/原生会话；文件/Diff 选区原文冻结，ACK 仅消费匹配草稿；真实工具结果有原生 ID，Git 不归因作者 | 隔离本地模型 + 官方 SDK + 当前包；定向自动化与视觉 |
| A5/A6 | 待答交互可重订阅；停止保留并暂停队列，明确继续消费一次；关窗后同一会话继续，旧代次不污染 | 真实 Electron/SDK 组合；已有正确竞态证据复用 |
| A2/A3/A6/A7/A10 | 明确失败与 unknown 不混同；unknown 不重发，重开保留冻结原文/新稿/历史；冷恢复无单写证据只读 | 现有跨真实对象回归 + 包内故障/重开 |
| A8/A12 | 默认仅浏览，文件/Git 边界与失败反馈；当前代表性内容可读可编辑，空白 Diff 可见，主题/密度保持引用 | 现有负例 + 新增/受影响 macOS GUI；不扩 M2 固定负载矩阵 |

## 2026-09-30 体验反馈与完成口径

用户询问 M1 是否已完成、是否应进入 M2、还有哪些未完成，以及最新候选能实际体验什么，并反馈界面简陋、无法有效试用。S1–S5 当前授权工程切片完成，不代表完整产品可持续使用，也不能把下一步仅写成等待用户认可。

当前源码确认的体验限制：`PreferenceToolbar` 的“新会话”是静态文字；选择项目入口仅在无 Thread 的空态显示，已有 Thread 后没有正常的新建/切换项目或会话入口。冷恢复保持只读，因此完全退出后恢复旧 Thread 无法继续执行，也没有 GUI 新建可执行 Thread 的自然出口。没有 GUI 认证和模型选择，真实执行依赖已有可用原生配置。直接打开正式候选不会自动启动确定性本地模型，免凭据试用需使用 [隔离启动器](../../validation/s5/README.md)。暂停非空队列的放弃后退出仍受 S3 09 待决影响。上述限制实质妨碍反复试用，不只是缺少验证记录。

后续建议先交付能反复使用的入口：配置/模型、项目/会话入口与清晰的主要操作流程，再按 M2 首版逐功能推进。此建议不是 M2 实施授权，不在本轮接入认证、多 Thread GUI 或改变恢复/退出策略。供应商与系统输入验证缺口、历史硬化复核票分别保留，不将所有未关闭票都称为已证实缺陷或 M2 的全局前置。
