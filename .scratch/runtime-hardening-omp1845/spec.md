## 1. 结论与目标

可以在本会话统一承接成果，不需要等待另一会话继续工作。必要的是修正已经证实的配置接缝、升级固定原生版本并补足运行时证据和故障边界；当前证据不支持照单实施整套新执行模型、审批数据库或目录租约。

最终升级目标按 2026-10-01 用户授权固定为 **OMP v18.4.6**，不写浮动 `latest`。官方 tag 对应 `8b25ad4a05625dde65df41d057756b4815f4837c`；官方 npm 的 coding-agent 和 utils 均固定 18.4.6，coding-agent 要求 Bun `>=1.3.14`。保持官方 SDK 薄宿主路线，暂沿用 Bun 1.3.14；实际兼容性由升级票验证。[升级方案](upgrade.md)给出资源、行为与回退顺序。

需要得到的结果：

1. A 发起的配置查询、认证操作和模型能力读取有明确身份，不会借用切换后的 B。
2. 配置观察路径不迁移、初始化或修复用户原生文件，不启动项目代码或隐含网络刷新；显式认证写入另走命令。
3. GUI 如实表达原生支持的推理能力、默认与关闭语义，应用后显示实际值。
4. 对有身份的原生 prompt 结果保存有限证据；ACK、prompt 结束、session settled、进程退出分别表达。
5. Main/Host/OMP 故障能够说明谁仍存活、哪些结果未知、允许何种恢复；不能只因断链宣布已停止。
6. 跨 Thread 编辑保留窗口内选区和有限撤销；不永久保存编辑器内部状态。

## 4. 原 Runtime 提案的取舍

| 提案内容 | 本轮决定建议及依据 |
| --- | --- |
| Main/SQLite 持有产品持久事实 | 保留。范围限定为 Thread、冻结提交、收据、有限原生结果观察及必要监督记录；真实执行、队列和历史仍由 OMP 拥有。 |
| Submission / Attempt / Message 分离 | 保留概念区别，但复用现有 `submissionId`、`requestId` 和目标身份。v18.4.5 提供 prompt 结果关联；不为每次命令再造一张同构 Attempt 表，不把 prompt 结束等同产品 Run。 |
| 所有副作用先写意图 | 限定为 App 发起的提交及确有恢复需求的启用命令。保留现有 prepared/dispatching 事务；不为每个原生工具、token、临时状态写 SQLite。停止和紧急清理不能依赖数据库可写。 |
| Reliable State 全部 Main→SQLite，持久 ACK 后确认 | 改为按数据类别处理：收据/结果证据先提交再报告持久成功，瞬时 control/queue 镜像可重查。Main 提交失败必须暴露覆盖缺口；Host 内存缓存不能承诺跨 Host 崩溃重放。 |
| UNKNOWN 自动查证 | 仅用精确身份的实时原生结果或真实权威证据查证。没有文件不证明没有执行；实时 prompt_result 不自动变成崩溃后可重读账本。未知不自动重发，用户新提交保留新 ID。 |
| 持久审批、Main policy、Runtime enforcement | 暂不建审批数据库。当前 generic confirm/select/input/editor 并非统一工具安全授权，且回答没有原生 ACK；迟到、过期和断链显示原生事实。未来真正权限命令另定义策略和执行门，不把记录用户点击当投递证明。 |
| 同目录一个 tool-capable Run、Mutation Lease | 不纳入。本规则改变 D-08 和基础契约的同目录多 Thread 基线，也会禁止本可并行的工作；目录租约不能证明原生会话跨 CLI 单写或拦住外部程序。若未来要求串行，再单独决定。 |
| UNKNOWN/孤儿时隔离并监督 | 保留对本次受管实例的停止/未知约束，先验证后最小修复。结果未知与进程存活未知分开；不因会话文件缺失释放、不仅凭 PID 杀进程，不引入新 Workspace 实体。 |
| terminate 或 adopt | 首轮推荐 terminate 与准确标中断，保留历史只读；旧 stdio 无可验证重连协议，不承诺 adopt。不能用新原生会话冒充恢复旧任务。 |
| epoch/seq/snapshot、双通道 | 保留当前 generation+订阅序号/水位；只在新增实际边界时加字段。控制和正文各自保序，prompt 结果不证明 Renderer 已收到最终正文；原生 message_end 与 snapshot 保证最终内容。 |
| 合帧、限流、公平调度和 warm eviction | 保留已有有界解码/请求表/投影与合帧。先测实际退化再加调度或回收策略；不把每 Thread 一个 Host、池化平台或暖保留作为本轮前置。 |
| Live / Native Data Adapter 与 fixtures | 按现有 protocol、Host、configuration 和 native-history 所有者落实。增加版本化真实样本和只读格式入口，不为命名统一新造中央适配平台。 |

## 5. dot 调研的吸收结果

| 条目 | 处理与验收归属 |
| --- | --- |
| R01 配置查询身份 | 当前缺陷，02 必修；覆盖跨 await 切换与迟到回包。 |
| R02 推理能力 | 当前缺陷，02 必修；依原生 metadata 而非品牌规则，包含 minimal、不可调档、禁止 off。 |
| R03 编辑连续性 | 05 产品改善已纳入认可范围；现有展开/收起正确行为保留，不声称已违反跨 Thread undo 的既定合同。 |
| R04 多条 steer | 保留原生消费模式，在 03/已有 M2 队列票按实际消费验收；不强制改成 all，不把逐轮消费叫丢失。 |
| R05 压缩与输入 | 03 加一个真实交错样本；压缩由 OMP 负责，不建 App 补偿调度。 |
| R06 退出与旧交互 | 04 覆盖必要真实故障，交互 ID/代次和过期拒答回归；不预设必须持久审批。 |
| R07 长文本与阅读 | 06 复核受影响的最终正文与近底手动滚动；完整负载留在 M2 06，研究参数不是新增硬门槛。 |
| R08 原生旧配置 | 已确认模型迁移写入纳入 02；账户缓存可见性差异仍是条件风险，用一个隔离样本核实，未证明不标认证缺陷。 |
| R09 已有存储/调度 | 保留现有事务、原文、ACK/错误分离和停止门控；旧有效测试继续回归。 |
| R10 续聊/备份/更新 | 保留将来触发条件；不开放冷写恢复，不加入 updater 或备份平台。 |

旧报告的“入口尚缺、冷只读缺验证”不覆盖 m2.6 已有包内证据；本轮针对改动重新验证相应路径，不把历史候选当新 SDK 验收。
