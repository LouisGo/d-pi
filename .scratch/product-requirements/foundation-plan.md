# 首版基础方案收敛

本页收敛首版验收、Composer 和变化记录三项。用户要求前期方案清楚后再动手；本轮仅文档、源码核实和设计，没有安装依赖、构建产品或编写交互原型。2026-09-25 用户对审查七项逐一回复，采纳主要建议并授权工程补齐。首版范围和工程行为由 D-23–D-26 与[基础契约](../../docs/architecture/foundation-contracts.md)收敛；依赖候选仍按原状态，不把设计就绪等同实测通过。已确认边界见[决定登记](../../docs/decisions.md)；完整最终需求见[需求](spec.md)。

## 1. 首版是一个什么交付

首版 M2 为 macOS 本地开发客户端：无需安装 OMP CLI，已有配置直接使用，新用户可由 GUI 完成原生配置；可打开本地项目、创建/切换/恢复 Thread、输入需求、处理 Agent 交互、检查项目文件和代码差异，并继续工作。不是只用于验证 API 的演示壳，也不是一次交付最终全集。

### 首版 M2 验收清单（内部 M1 是子集，见基础契约 §8）

| 编号 | 必须完成的用户路径 | 通过标准 |
| --- | --- | --- |

V1-04 纳入本轮收敛的 M2 范围；M1 先完成文字/选区内部闭环，不要求全附件先完成。PDF 等没有可用转换/原生接入时，该项不得判通过：先给出证据和方案，不能静默降级为只发送文件名。V1-02 保留已有配置的模型选择；首版新增认证入口按 D-23 限定两条，其他认证待接入状态明确呈现。

### 保留在后续阶段，不删除最终需求

- 子 Agent 默认模型/档位 GUI 设置（D-27，原生通路已验证，后续 spawn 生效）。
- Monaco 编辑与 TS/JS 项目语言服务；首版读取已经包含未来模型/文件标识所需的基础。
- Side Chat、浏览器、终端、PNG 分享、Git 写操作、内置 worktree 创建/迁移/清理，以及历史编辑/分叉/树导航的精细 GUI；最终定义不变，按接口与产品场景逐项加入。
- Agent Changes / Run Changes / Review / Revert 的完整业务界面；首版保留清晰数据来源与组件边界，不提前显示不可用操作。
- 不包含自由分屏、完整 IDE 扩展/调试体系、完整通用 Git 客户端。

### 初始化接入方案

先由包内 Runtime 在原生配置上下文查询配置、认证、模型和能力；已有可用状态直接进入。新用户 GUI 按“OpenAI 账户登录或 DeepSeek API key → 完成认证 → 选择模型/必要默认设置 → 检查并开始”组织，允许取消与重试。可选搜索、语音、主题等不作为开始文字会话的额外前置要求。

这不是照搬 TUI 屏幕。v18.3.0 的 `createSetupHost` 已把配置/模型/认证作用与 TUI 场景连接，说明可复用职责；它依赖 TUI context，不是已可直接调用的桌面 RPC。必须优先调用可用原生接口，必要时暴露薄适配，不重写认证协议或配置合并。不能用 TUI 的 setupVersion 是否写入作为唯一可用性判定，也不擅自替 TUI 标记全部向导完成。

## 2. Composer：推荐直接 ProseMirror，自建有限的业务层

### 推荐与原因

推荐直接使用 ProseMirror 的模型、视图、事务、历史与键盘模块，自建 OMP Composer。理由是交互核心在结构化引用、附件状态、草稿与原生提交语义，而不是完整文档工具栏；我们需要清楚控制这些行为。不是因为已证实 Tiptap/Lexical 不行，也不依赖尚未证实的 Codex App 实现说法。

Tiptap 是回退比较项：只有直接路线在 React 集成、节点交互或维护量上出现具体问题，才用同样场景评估最小 Tiptap 是否减少成本；不同时实现两套完整 Composer，不默认 fork ProseMirror。选择理由与资料见[研究](composer-research.md)。该推荐尚待验证与方案确认，不标记为已采用。

### 单一所有权

| 数据 | 所有者 | 约束 |
| --- | --- | --- |
| 文字、换行、引用节点、选区、撤销历史 | 编辑器实例（具体库待 P-02 验证） | React 不每次流式更新都重建 editor；不另存第二份可写文字正文 |
| 附件内容、预览、处理任务 | App 附件服务 | 编辑器仅持 ID；二进制不进入撤销栈；删除引用不等于立刻删除其他草稿仍引用的内容 |
| 每 Thread 的持久草稿 | App 草稿存储 | 使用带版本的业务 DTO，不把编辑器内部 JSON 作为全应用/OMP 的永久协议；本地编辑快照由适配层处理 |
| 发送中的内容包 | 宿主提交适配 | 一次提交冻结内容、附件和引用，随后编辑草稿不能改动已提交内容；映射到 OMP 支持的消息/图片/资源形式 |
| 接受后的消息与队列 | OMP | 不把 GUI 草稿清除当作 Runtime 已接受；结果不明时重同步而非自动重复提交 |

### 建议输入规则

- 普通 Enter 发送、Shift+Enter 换行；IME 组合期间及候选确认不触发发送。@ 菜单打开时 Enter 先确认候选。发送快捷键设定是本方案建议，不能当成用户已有明确选择。
- 引用显示路径与行号；建议选区在附加时保存原文，@ 文件在发送准备阶段读取并冻结内容。内容变化时保留来源并提示，不把旧行号装作最新定位。该捕获语义已随本轮第 4 项采纳，详见基础契约 §4。
- 发送前等待必要附件处理完成；失败项明确定位，用户可以重试/移除，禁止静默漏发。大小/类型/模型限制由能力检查返回，不硬编码“所有 PDF 都可直接发给任何模型”。
- 按[提交交接合同](../../docs/architecture/foundation-contracts.md#2-提交交接b2)确认并持久化业务接受证据后，清理对应版本草稿；首个 RPC success 不足以触发清理。后续失败保留原提交内容，提交过程中新增的输入保留。切换 Thread、窗口刷新、失败重试均不串草稿。
- OMP 原生输入支持与 GUI 接受类型分开。v18.3.0 RPC prompt 明确有 message/images，不据此假定任意文件/PDF 都有通用二进制字段；优先核实原生引用/读取/转换路径。

### 开工前与实现后的验证分开

本轮先确定上述合同和验证方案，不编写原型。用户同意进入技术验证阶段后，先做隔离的 Composer 可行性样本，不能把它当成正式产品源码；若样本证明路线有问题，记录证据与取代提议后再调整。

样本覆盖：系统中文输入法（拼音候选确认）、英文、多段输入、@ 查询过期结果、节点边界选择/删除/撤销、混合粘贴、多附件失败、提交中切 Thread、失联后的重复提交风险、恢复与流式消息同时更新。通过真实 Electron GUI 操作验证 IME，模拟键盘测试不能替代它。性能记录机器、版本、输入/消息规模、输入延迟和内存变化；不得先编造一个达标数字或用静态截图代替行为验证。

## 3. 变化记录：先明确证据，再展示 Diff

### 三种东西分别呈现

| 视图/来源 | 比较对象 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| Git 当前变化 | HEAD ↔ index；index ↔ 工作区；未跟踪文件另列 | 当前仓库状态 | 不是自动等于本次 Agent 的修改 |
| 工具修改证据 | 原生工具实际返回的 patch/结果，关联 toolCallId 和会话 | 工具报告过什么；有可靠前后文本时可画 Diff | 调用参数不是修改成功证明；可能缺前文或含截断，不覆盖任意 shell/后台/外部修改 |
| Run 期间观察到的变化（后续） | 明确的起止采样与覆盖清单 | 在该观察区间发现的差异 | 不自动证明作者，也不代表文件系统原子快照 |

2026-09-25 用户已确认首版交付前两种，完整 Run Changes 和逐次修改归属后续接入（D-20）。不能用“全部 AI 改动”给它们命名。工具没有可靠前文时展示结果与路径，并能打开该文件当前 Git 差异，但清楚标注这是另一来源；不能用 HEAD 当作该工具执行前内容拼出虚假的操作 Diff。非 Git 项目仍可查看文件和工具结果；没有基线就不伪造完整历史差异。

Agent Changes 是后续按执行来源组织的产品视图，不能简单等同工具路径集合或 Run 区间差异。同一文件被用户和 Agent 同时修改时，不把整份文件归为 Agent。这个边界从首版就保留。

### 原生证据核实（固定 v18.3.0，源码检查，未运行实验）

- `AgentEvent` 包含 agent/turn/tool 开始结束；工具事件有 toolCallId、参数和结果。`agent_end` 在 Session 扩展里有可选 isTerminal，false 表示异步后续还可能恢复。不能把一次模型 turn 或任意 agent_end 都当作产品 Run 完成。
- `RpcCommand` 中已检查的类型未提供通用全文件变更账本/持久前后快照导出命令；这是所检查接口范围的结论，不宣称整个 OMP 无其他能力。
- `EditStore` 是会话持有的原生编辑快照，read/search/write 等用于 hashline 标记和编辑；不能由其存在推导 GUI 已获得持久、完整的改动历史。
- `write` 的普通成功结果可只含 resolvedPath/madeExecutable/diagnostics，没有完整 before/after；内部可能经写后处理产生 finalContent，不能直接把输入参数当最终磁盘内容。
- checkpoint/rewind 的实现与记录围绕会话上下文，不能将工具摘要中“git-based checkpoint”一句当成磁盘恢复保证。

来源：[事件类型](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/agent/src/types.ts)、[Session 事件](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/session/agent-session-events.ts)、[RPC 类型](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/modes/rpc/rpc-types.ts)、[EditStore](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/edit/store.ts)、[write](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/tools/write.ts)、[checkpoint](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/tools/checkpoint.ts)、[初始化 Host](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/modes/setup.ts)。

### 组件边界与数据合同建议

1. Git 读取服务返回仓库身份、HEAD/index/worktree 的明确来源和捕获时点，区分新增、删除、重命名、二进制、未合并、子模块与无 HEAD。利用成熟 Git 实现，不改 index、不创建临时提交、不 stash 用户修改来采样。
2. 工具证据适配层保存会话/实例代次、toolCallId、原生结果来源及错误/截断状态。先复用 OMP 原记录，仅在实际无法恢复时保存必要补充证据，不另造执行历史。
3. Monaco Diff 仅接收明确的左右内容与来源标签，不读 Git、不推断作者、不决定回退动作。缺失内容、二进制或权限失败提供对应说明，不以空字符串伪装空文件。
4. 活动 Diff 更新前后检查版本变化；文件/索引在读取期间变化时重读或显示陈旧状态，不宣称跨多文件一致快照。编码与换行变化保留；大文件/截断必须显式标注。
5. 首版不引入隐藏 Git 分支、全工作区快照库或文件系统拦截器。未来如需 Run Changes，再评估原生接口与有边界的采样，不提前搭建持久化平台。

### 为 Run / Review / Revert 留位置，不提前承诺能力

未来数据应能携带 Thread、执行区间、触发输入、工具证据、采样时间及覆盖缺口；具体实体数量和存储方式等需求进入该阶段再定。可建议 Run 为宿主观察的一个执行周期，但不在本轮确定它与 prompt/turn/agent_end 一一对应；排队追加、干预、子 Agent 延迟返回和崩溃都必须先核实。

Review 的目标应关联具体内容版本，内容改变不能继续沿用“已查看”而不提示。Revert 要明确操作对象、目标版本、当前版本前置条件、并发修改和失败处理后才能启用；目前不选 Git 命令、不写实现。OMP 原生会话回退继续遵守既定定义，不承诺磁盘恢复。

### 必验反例

- 启动前已有用户改动，Agent 只改一行：Git 视图显示全部当前变化，工具证据不能把已有改动算成 Agent。
- Agent 通过 shell 或子 Agent 改文件：不能只监听 edit/write 后宣称改动完整。
- 外部编辑器并发修改：标明归属不可确定，不允许据此做自动回退。
- 新文件/删除/重命名、未暂存/已暂存并存、初始仓库无 HEAD、冲突状态：两侧来源准确。
- 只读项目、无 Git、超大/二进制文件、符号链接越界：给出真实边界，不破坏项目；明确批准范围外的读取按[基础契约 §5](../../docs/architecture/foundation-contracts.md#5-最小权限与信任b5)处理。
- 执行中崩溃/重连：缺失基线就是缺失，不能用恢复时磁盘状态倒填运行前快照。

## 4. 现在的完成条件与下一步

- 已确认决定保持锁定；本轮七项答复的落实、基础契约和阶段范围已收敛，审查关闭状态见 preflight-review。
- 首版 Diff 的“Git 当前差异 + 工具证据”与完整 Run 归属后续的顺序已确认，不再重复询问。首版其他范围按 D-26 分阶段交付；Composer 保持优先验证路线，不要求用户凭库名选择。本次确认不构成对全部方案或开工的授权。
- 用户确认设计后，先进入明确授权的隔离技术验证，再依据结果锁定依赖并启动产品实现。当前不启动原型、安装依赖或创建生产骨架。
- 初始化认证桥接、附件/PDF、Monaco worker、Composer IME 和变化来源按本文合同验证。失败先定位实现/接口问题；确实需要改变用户决定时提出证据、影响、替代方案，不自动换库或削减需求。
- 已知证据不能保证零返工；目的在于固定行为和所有权，使验证暴露的局部问题不会引起无记录的方向漂移。
