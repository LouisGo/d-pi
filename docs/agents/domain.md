# 领域文档约定

本仓库使用单一领域上下文：根 [CONTEXT.md](../../CONTEXT.md) 定义概念与术语，[docs/adr/](../adr/) 保存架构决定；状态与取代关系登记在 [decisions.md](../decisions.md)。

涉及领域概念、功能行为或架构设计时，读取 CONTEXT 和受影响 ADR；普通文字、样式任务不要求通读。输出、任务和测试使用已定义术语，不用近义词悄悄改变含义。实现字段与算法留在相关合同或源码，避免把词汇表写成第二份技术规格。

概念缺失时，先确认现有术语是否足够；确需澄清才补充领域定义。可使用 `domain-modeling` 帮助整理，但无需先安装或执行其他 skill。不要只因目录不完整就生成文档体系。

必读依据缺失或冲突影响当前结论时，明确说明缺口及影响，继续不依赖它的工作；不要静默假设决定不存在。要改变既有决定时，列出原决定、证据、替代方案与影响，按仓库的决定连续性规则处理，并保留取代关系。
