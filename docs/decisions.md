# 产品与技术决定登记

更新：2026-09-30。目的：让新的 AI/开发者能够分清用户决定、历史工程基线、提议和证据，防止无记录地推翻方向。本文件是索引，不复制完整规格；行为细节以链接目标为准。有矛盾不得用文件更新时间或措辞强弱擅自决定。

## 状态与变更规则

- **已确认**：源于用户明确决定或 accepted ADR；实施必须遵循。
- **沿用基线**：历史记录中已有工程方向，本轮恢复保留；不是每一项都由用户逐包确认。按需接入与复核版本，不能整套清零。
- **提议**：助手推荐或尚未确认的方案，不因写进文档就成为用户决定。已确认但尚未实测的合同仍然有效，不能降为提议；验收状态单独记录。
- **已取代**：留存旧理由与新决定引用，不删除历史。
- **已验证**是证据属性，不是产品批准状态；必须写清版本、场景与未覆盖项。

修改已确认决定前，先记录：旧决定 ID、实际证据、为什么现有方案不足、替代方案、对行为/数据/依赖/平台的影响。涉及用户已定方向、重大范围取舍或不能判断的概念冲突，必须与用户确认；未确认前保持原决定有效。常规、可逆且不改变决定的实现细节可自主处理，避免每项都上升为架构决策。

用户后续明确指令可以取代旧决定；更新对应规格并追加日期/依据，标记取代关系，不静默覆盖或删除原记录。不从外部文章、上游默认值、旧代码依赖或某模型偏好推导用户已改变主意。
