# 开发基础契约

日期：2026-09-25。依据：用户对审查 B1–B7 的逐项答复。B1/B2/B4 采纳建议，B3 限定首版认证入口，B5 要求简单权限选项，B6/B7 授权工程补齐与阶段划分。本文是据此确定的工程设计，**不是实现或实测结果**。决定索引见 [D-23 至 D-26](../decisions.md)，审查来源见 [preflight](../../.scratch/product-requirements/preflight-review.md)。数值为初始工程预算，可按测量记录调整，不属于用户逐项承诺。

## 1. 身份、持久化与生命周期（B1）

- `threadId` 为 App 生成的稳定 ID，创建草稿即分配，重启、换模型、OMP 重启不改变。`nativeSessionRef` 可空，仅在原生确认后绑定，包含配置上下文标识、原生 ID/路径；路径不是已经落盘的证明。没有落盘记录时保留 Thread 与草稿，恢复为未启动/中断，不伪造会话历史。
- `workspaceId` 对应规范化工作目录及其关联项目；原目录与 worktree 独立标识。同目录多 Thread 明显提示共享文件，不强制串行。目录丢失/移动后暂停执行，由用户重新关联，不自动在同名目录继续。
- `processInstanceId`、`connectionGeneration` 每次实例/连接变化重新分配；过期回执不能更新新连接。原生分叉创建新的 Thread 与会话引用，保存父 Thread/原生条目关联；树内导航不新建 Thread。
- Main 集中写 App 元数据，带 schemaVersion/revision；串行更新、临时文件落盘后原子替换、保留上一个有效版本。禁止多个 Renderer 覆盖整份数据；未知更高版本只读，不静默重置。OMP 原生会话仍由 OMP 写，业务补充数据不冒充原生历史。
- 一个 utility SessionHost 管多个独立 OMP，一个活跃顶层会话一个 OMP。Main 监督 Host，Host 监督自己的 OMP；子 Agent 属于 OMP。单个 OMP 崩溃只中断其 Thread；Host 崩溃使所有所管连接中断。先确认并清理本次实例残留，再允许恢复，不能只靠 PID 杀进程或接回旧 stdio。
- App 内同一原生会话只有一个执行拥有者，采用单 App 实例入口。**不声称已有跨 CLI 会话锁。** 首版执行恢复限于 App 管理、可确认未占用的记录；CLI 历史导入执行后排。跨程序原生锁在 G1 核实；无法确认占用时允许查看，阻止追加，提示关闭原运行入口后重查，不能自动强占。即便检测未发现冲突，也不能宣称可阻止不遵循锁的外部写入。

| 状态/动作 | 合同 |
| --- | --- |
| 浏览已有历史 | 不启动 Agent，不加载项目可执行扩展；只读历史解析与执行加载分离 |
| 开始/恢复任务 | 校验配置、目录、信任、会话占用后启动；未就绪不开放发送 |
| 关窗/刷新 | OMP 继续，后台仍消费输出；重开接快照再接增量 |
| 空闲回收 | 仅无执行、无排队、无待交互、无后台子任务且已持久化的实例可回收 |
| 等待退出 | 队列/待交互/后台活动算未完成；可返回窗口回答，保留取消退出入口 |
| 停止后退出 | 原生 abort 不等于清队列；检查实际终止，超时显示残留并提供明确强制结束，不能静默退出 |
| 崩溃 | 标记中断/提交结果未知；不自动重放输入或副作用，不把进程退出等同任务成功 |

## 2. 提交交接（B2）

每次用户提交分配 `submissionId`，绑定 threadId、草稿 revision、冻结内容包、模式（普通/排队/干预），traceId 只用于追踪。Main 管最小持久收据，Host 负责 RPC 关联，OMP 负责接受后的真实执行/队列。

状态：`preparing → prepared → dispatching → accepted`；明确拒绝为 `rejected`，本地准备中取消为 `cancelled`；发送后断链/超时/宿主崩溃且缺可靠证据为 `unknown`。accepted 不是 started/completed。Host 必须等 prepared 与 dispatching 收据落盘确认后才写 OMP；原生 ACK 到达后持久记录接受证据，再通知 Renderer 清除对应草稿版本。持久收据失败不推进发送，回执保存失败保留 unknown。

- ACK 丢失不能凭相同文本、队列长度或时间相近认定已接受；只在原生明确关联证据存在时解除 unknown。App submissionId 不能创造 OMP exactly-once 保证。
- unknown 保留冻结内容与“接收结果无法确认”标记；用户可查看历史/队列并显式重新发送，产生新 submissionId、关联原提交并提示可能重复。禁止自动重试，未确认接受前不静默清空原输入；提交期间新编辑版本始终保留。
- 同一 submissionId 的本地重复点击/重复 IPC 只能返回已知状态，不重复派发。重启发现 dispatching 按 unknown 恢复；prepared 可由用户继续提交。
- 收据保存身份、状态、时间、原生关联证据与内容包引用，不另记模型执行历史。accepted 内容在原生持久化和引用可恢复性已确认后可解除临时保留；unknown 内容不能被普通缓存 GC 清掉。

## 3. 配置与首版认证（B3）

**首版新增/修复认证入口只交付两条：OpenAI 账户登录（OMP 的 openai-codex 路线）和 DeepSeek API key。** OpenAI API key 与 ChatGPT/Codex 账户登录不是一个认证入口，界面不能混称。这里收敛的是 GUI 初始化开发和验收范围；已有其他可用原生 provider/model 继续展示复用，不新增模型品牌拦截。其他 provider 的新增 GUI 认证后续逐项做，不能假设只是换名称：其他 OAuth、企业身份、本地服务等仍须各自验收。

- `configContextId` 标识解析后的配置根、profile、cwd 与非秘密的来源信息；真实环境值/凭据由宿主使用，不放进 UI 状态/日志。所有配置读取、认证及 OMP 执行使用同一上下文。
- 正常已配置路径零配置进入。Finder 启动缺少终端环境时，区分 absent / incomplete / incompatible / inaccessible；GUI 可选择原生配置根及必要环境来源，展示来源与作用域。不能误判成新用户后暗建默认配置，也不自动执行任意 shell startup 文件以“修复环境”。
- 不兼容格式禁止写入，不自动迁移外部 CLI；提供只读诊断、选择兼容上下文及明确修复说明。原生接口写设置，保存前重读、比较目标 revision/内容，保存后回读；App 内串行不冒充外部 CLI 互斥，record 冲突要求刷新重做，不能盲覆盖。
- 认证由原生实现管理 token、刷新及持久化；GUI 仅传秘密输入/显示挑战、取消与进度。OAuth 用系统浏览器，不依赖未来内置浏览器；回调/state/超时由原生路径处理，结束释放监听。API key 不进入命令行参数、日志或 App 偏好，走受控输入通道。新 key 验证/保存失败保留已有有效认证，不先删旧值。
- 原生设置 CLI 不等于完整认证 RPC。G1 确认随包产物能否暴露原生 auth；允许短生命周期的随包薄桥接（复用固定版本原生模块），不先建常驻服务、不自写 OAuth、不维护 Runtime fork。若需要长期 fork 或无安全可打包入口，阻塞认证切片，带证据对齐，不偷偷换登录方式。
- 验收分别覆盖：新用户完成两条入口、已有配置复用、取消/超时/无网络/无可用模型、认证刷新、App 重启、Finder 环境差异、旧配置不被误覆盖。列出模型不等于请求可用，不用真实计费请求当无提示的配置探针。

## 4. 内容包与附件（B4）

ProseMirror 管编辑状态，App 管版本化草稿与附件，提交适配生成 OMP 能接收的 payload。直接 ProseMirror 为优先验证路线，遇到具体集成问题才比较最小 Tiptap。

- 粘贴/拖入时将图片和附件复制到 App 私有内容存储并校验成功，之后不依赖外部路径仍存在。二进制按内容摘要去重；每个引用仍保留独立来源、文件名/MIME、字节数、捕获时间。不能因同内容而混淆用户多次附加。
- 编辑器选区在附加时冻结文字、路径、行号及文件版本；@ 文件在发送准备阶段读取冻结，显示“发送时读取”，文件消失/越权则阻止该次发送。排队后内容不随磁盘变化。所有转换记录输入摘要、转换版本、输出形式和覆盖缺口。
- 内容状态为 preparing / ready / failed，只有全部必需项 ready 才提交。内容包不可变；修改草稿产生新版本。准备阶段超限/失败可移除或重试，不自动截断、改模型、只发送文件名。
- 文本文件明确编码；二进制走支持的原生资源/图片能力，不能假装都是文本。PDF 优先原生可靠通路，否则本地解析文字并按需渲染页面；扫描/图表不能仅抽空文本即宣告成功。向用户展示转换结果和损失，模型不支持需要的图像时阻止发送该表示并给出换模型/显式仅文本选项。默认不用第三方文档解析服务。G1 验证解析/渲染与模型适配，无法完整覆盖时不判 V1-04 通过。
- 首轮预算：单源文件 25 MiB、单提交原始内容 100 MiB、PDF 100 页，实际模型限制更严则从严；预检后报具体限制，可记录原因调整，不隐藏处理大文件。内容存储软上限 1 GiB，达到上限只清无人引用的派生缓存；活跃草稿/准备提交/unknown 收据固定保留，容量仍不足时明确拒绝新增而非删用户输入。
- 原件、派生项有引用计数与一致性扫描；最后引用释放后延迟 7 天清理，可手动清理无人引用缓存。原生历史未自持久附件时保留 App 引用依赖；不能假设 accepted 即可删原件。损坏/丢失显式标出并允许重新附加。私有文件限制本机权限，日志无正文/秘密；这些业务内容不是诊断日志。

## 5. 最小权限与信任（B5）

先提供三个清楚的层次，不建设规则编辑器：

| 选项 | 实际含义 |
| --- | --- |
| 仅浏览（新目录默认） | App 文件树/只读代码/Git 差异；不启动项目 Agent、shell、项目扩展或语言服务进程；只读服务不得加载项目代码 |
| 信任当前文件夹（常用） | 允许此目录的任务启动及原生项目配置/扩展加载；App 文件接口限此根和显式选中文件；**这是项目执行信任，不是 OMP 操作系统目录沙箱** |
| 完全访问（高级显式选择） | 放宽 App 宿主文件接口的项目根限制，仍受 OS 用户权限；不获得管理员权限、不绕过 OMP 原生审批、不默认对未来所有项目生效 |

必要补充只有“额外授权文件/文件夹”列表，来自用户的文件选择/拖入，首版只授读取；可查看和撤销。信任/完全访问保存在规范化目录维度，不通过父目录信任自动覆盖所有项目。撤销阻止新操作，正在执行任务需停止后才可声称已降级；不能承诺撤销收回已交给 OMP 的数据。

Renderer Node 关闭、contextIsolation 和 sandbox 开启，受限 preload、IPC schema/source/Thread/资源归属校验。Main/宿主规范化路径、解析 symlink 并校验实际目标，模型输出路径不构成授权；文件句柄打开时复核，不能仅作字符串前缀判断。App 的“只读 Git”调用禁止会执行用户项目脚本的外部 diff/textconv 等选项。

OMP shell/工具原生权限和 App 文件接口是两个执行面。项目信任说明须明确 Agent 可能访问当前 OS 用户可访问的其他资源；未验证原生隔离前不得出现“Agent 仅能改当前目录”的承诺。如果后续要求真正工具沙箱，另行评估。Side Chat 真只读必须在工具注册/能力层限制；无法证明就不接可写工具，不能只放一段只读 prompt。

## 6. 有界事件与恢复（B6）

| 数据类别 | 策略 |
| --- | --- |
| 流式文字、瞬时进度 | 同一 block 内合并；工具/交互/终态前刷新，完整正文可分页，不保留每个 token 事件 |
| 消息/工具/交互/终态 | 保序投影，不能仅留下最后一条状态；可从原生持久化重读的记录用原生引用 |
| 无原生重读保证的工具/子 Agent 输出 | 只保存恢复 UI 必需的内容与原生关联，App 有界补充存储；不据此重建 Agent 上下文 |
| 诊断 | 独立有界队列/轮转，与业务输出存储分离；详见 diagnostics |

Host 按 connectionGeneration + 单调 seq 产生投影；快照包含 watermark，先订阅并缓冲增量，再应用快照并接 > watermark 事件。缺号触发重同步，旧代次丢弃。历史分页独立于实时尾部；后台无窗口仍读取。持久化缺口、原生记录未落盘、超限截断均有用户可见占位与范围，不显示虚假完整。

初始每活跃会话内存尾部预算 8 MiB，事件补充存储每 Thread 100 MiB、全 App 1 GiB；超限先回收已可原生重读的缓存，再转分页。无可回收空间时记录缺口、警示恢复覆盖不足；不阻塞读 stdout 导致子进程卡死，不删用户待答交互/未决提交。预算不约束 OMP 自己的磁盘记录，界面不得把 App 缓存清理叫删除原生会话。

## 7. 诊断与性能验收预算（B6）

沿用 D-21/D-22；Main 负责日志设施，业务走实际 Renderer→Host 或 Main 路径。跨边界共享 traceId，错误类型、观察点/报告源/归因/恢复责任分开。日志失败不阻断正常任务，但必须有独立的退化指示与 dropped 计数。

初始实现预算：每进程日志待发队列 1 MiB / 1000 条（先到者）；批量最多 100 条/100 ms，关闭时有界 drain 2 s。单日志文件 10 MiB、轮转总量 100 MiB、最多保留 7 天。关键错误优先于 debug，但不承诺异常风暴零丢失；debug 限时 15 分钟，默认不记 token 级事件、正文或秘密。磁盘满/写失败不得递归记日志形成风暴。

固定机器与版本、相同输入/输出重放，比较日志开关各 5 次的中位数及尾延迟：默认诊断使 p95 输入反馈增加 ≤5 ms，任务完成时间增加 ≤3%，稳定内存增加 ≤20 MiB；输入反馈绝对 p95 ≤50 ms。以上是待测验收目标，不是已实现数字。控制其他变量、记录样本数量和方差；有波动不能挑最好一次宣称通过。

负载至少覆盖：3 个并行 Thread、累计 10000 条消息、单工具 10 MiB 输出、后台持续 30 分钟、20000 字 Composer 编辑及中文 IME、多附件准备、窗口重开、日志磁盘满和慢写。队列/缓存不越预算，停止产出后内存趋稳；长会话原生/业务数据仍可增长，需分别报告，不能把全部 RSS 归给日志。真实模型网络延迟不用于归因本地开销；确定性样本测量与真实 OMP GUI 路径验收都需要。

## 8. 开发入口、里程碑与门槛（B7）

设计层已可进入分阶段开发；本轮仅交付文档，不启动实现。后续开发首先处理 G1，不要求再进行一轮泛化选型。后续功能的细节不阻塞基础工作；会改变用户承诺或要求 Runtime fork 的发现才重新对齐。

| 阶段 | 交付与出门条件 |
| --- | --- |
| G1 接口与输入验证 | 隔离临时配置，验证认证薄桥接、原生会话占用/恢复、ACK 证据、项目加载时点、附件/PDF 与 Composer IME/Monaco worker。逐项记录能力、缺口与可行替代；不要求先做所有 UI，不接个人凭据作自动实验 |
| M1 内部可运行 | 已有可用原生配置、一个前台任务完整闭环、文字/选区、交互/停止/排队、只读文件与 D-20 Diff、提交恢复、各层诊断和故障路径。基础身份支持多 Thread，但不要求此时多任务 UI 全验收 |
| M2 首版完整验收 | foundation V1-00–10：两种新用户认证、多 Thread 并行、全部指定输入、长输出/恢复、macOS 本地包；仅已验证组合标支持。逐项真实 GUI 证据，含性能与故障测试；局部失败不能用 M1 通过代替 |
| M3 后续渐进 | 子 Agent 默认设置 GUI、历史操作精细 UI、Monaco 编辑/语言服务、Side Chat、浏览器、终端、PNG 分享、Git 写操作/worktree 管理，按依赖逐项规划，不固定全部同时交付 |

G1 为相应切片的实现门槛：认证受阻不阻塞 M1 的已有配置闭环，但阻止 M2 认证通过；IME 失败阻止 Composer 定案；不能保证会话单写则限制恢复入口；权限未可执行就不显示虚假受限模式。性能验证随 M1/M2 真负载开展，不要求在零代码阶段“证明无感”。

开发前检查：需求→决定→本文合同→该切片验收场景有对应关系；引用固定依赖版本/证据；保留完整归档；先审阅工作区恢复内容再形成 Git 基线。当前未获提交/推送指令，不能以尚未提交为由偷偷提交，也不能声称已远端保全。

- [providers](https://github.com/can1357/oh-my-pi/blob/v18.3.0/docs/providers.md)区分 provider 身份、原生凭据解析、`omp login` 与 API key；列出 `openai-codex` 和 `deepseek`，支持本轮入口划分。CLI 登录存在不等于稳定的 GUI 结构化协议。

- [SessionManager](https://github.com/can1357/oh-my-pi/blob/v18.3.0/packages/coding-agent/src/session/session-manager.ts)的 peekSessionInit 注释提及 open 的 single-writer lock；本轮未追完底层锁及不同入口的遵循范围，不可仅凭注释断言跨 CLI 互斥已成立。open 还存在目录不可用时回退 cwd 的路径，App 必须在恢复前检查目录并要求显式重新关联，不能照搬回退而悄悄切项目。

原生版本升级需复核受影响接口，不用动态 main 分支的行为替代固定版本验收。调查结论是有可复用基础且剩余问题已有切片门槛，不是所有 G1 风险已经消失。
